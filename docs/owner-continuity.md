# QQ 主人私聊与桌面的连续交谈

可信的 QQ 主人私聊与桌面使用同一个角色视图：按时间合并最近交谈、共享角色的兴趣和未完打算、近期交流偏好、长期精确约定与语义记忆。QQ 发送仍回到原会话，不在桌面重复朗读。其他联系人、群聊以及显式隔离的渠道不获得这份私人连续性。群聊中自称主人不能提升权限。

## 原文、约定与来源

原始交谈继续保存在原有加密档案中，不迁移、不覆盖。`ha.continuity-packets/index` 只保存长消息来源编号，启动时为现有最近记录补建索引。上下文在预算内保留最近两份长原文（合计最多 16000 字节），供角色与审核连接完整核对，不能把它们当作系统规则。超出窗口的内容仍可通过受控档案搜索读取。

`ha.continuity` 保存精确约定的原句、解释、来源版本、时间和有效状态。角色可调用 `continuity.list` / `continuity.note`；已启用的审核连接也可在最终回复或沉默通过时提出最多八项更新，不增加额外模型连接。普通 JSON 连接兼容省略更新列表，严格结构化连接要求返回列表，没有更新时为空数组。

写入需要真实、可访问的用户消息来源和逐字原句；更新需要当前版本，旧消息不能覆盖来自更新消息的纠正或撤回。`persona_proposal` 保持待审核，不自动改核心人设、发展阶段或工具权限。记得某个要求不代表角色无条件答应。故事、引用和普通叙述不自动成为约定。最多保存 64 项，每轮模型视图最多 32 项 / 18000 字节，可按编号读取；达到边界返回明确回执，不悄悄覆盖旧项。

QQ 主人的 `memory.remember/revise/compact`、角色兴趣和状态操作通过原有受控桌面桥接写入统一角色仓库。来源仍指向 QQ 的加密原文。界面只公开数量和运行状态，不展示私人记忆正文。

## 缓存与撤回

新字段进入缓存会话准备之前的完整事件帧，审核读取程序展开的当前帧，不能误审第一轮旧输入。精确约定属于状态差异，不通过重写历史请求更新。工具声明与已发送回执保持原有缓存布局。

共享来源的可访问性传播支持带根标记的 `ha.archive/ha.memory`。QQ 的会话投影额外检查桌面访问与对话重建版本；撤回来源后必须重建，完整的后续模型请求也不得含该来源。原始档案继续保留。角色记忆来源不可用时，对应精确约定不再注入。桌面重建工作上下文也会排除主人 QQ 私聊中旧的角色对白，保留用户原文和精确约定，不把另一端的旧措辞重新引入。

## 边界与验证

桌面与 QQ 的传输媒介、附件、当前会话身份和展示方式仍有区别；一致指连续的角色、记忆与规则，不能保证两次采样逐字相同。模型仍须主动理解并提出约定；完整原文与审核提取减少遗漏，不能承诺自动无遗漏理解任意长文。单条输入上限 65536 UTF-8 字节，HTTP 消息封装上限 256 KiB。

`OwnerContinuity.cpp` 验证结构、来源隐藏传播、长原文索引和审核装配。`OwnerContinuity.mjs` 通过真实后台、NapCat 插件和隔离假 OneBot/模型服务验证 JSON/native 两条路径：跨端接续、重启、精确称呼与口令、纠正/撤回、旧原文复活拒绝、他人与群聊隔离、完整缓存前缀移除和磁盘加密。

真实模型的隔离实验还验证了五轮交谈、换话题、修改称呼、撤回口令及后台重启，未导入正式私人对话。运行证据放在忽略目录 `artifacts/owner-continuity` 与对应独立构建的 `integration` 下。不得把实验人物称呼或口令写入正式角色记忆。
