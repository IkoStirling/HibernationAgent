# 模型输入缓存复用

本次保持角色、独立审核、工具验证、记忆来源与可见性、后台规划和行为队列的分工。
不保存模型回答作为命中缓存的替代品，也不延长或扩大角色可访问的档案。

## 请求布局

- 固定角色规则、人设和执行协议继续放在 system。连续状态、现场能力与插件快照
  移到本轮 user 事件的 `authoritative_state`、`current_capabilities`、`body`。
- 事件 JSON 的字段和类型保持原契约，序列化时将授权历史放到时间、事件 ID 与
  现场快照之前。历史仍受现有选择、预算、摘要和可见性规则约束；不为提高命中率
  保留已经撤销的来源或伪造旧时间。
- 审核输入先放本轮依据，再放变化的回执和候选；后台规划先放记忆与经历，再放
  实时状态。没有删除独立审核，没有将资料升级为 system 指令。
- 同一轮各次调用保持相同工具定义与输出 Schema。结束阶段用现有指令要求
  reply/silence；程序在审核和执行前阻止超限 call。可见工具并不授予额外执行次数。
  权限、模型/Schema 或插件配置变更仍然可以使前缀变化。

这提升稳定前缀的复用机会，但不是完整追加式聊天重构。历史滚动裁剪、相关记忆
变化、图像替换和必要的回执压缩仍可能打断后部前缀。DeepSeek 的落盘与命中是
服务端尽力而为，不承诺具体百分比，不为预热缓存而发出付费请求。

## 用量与检查

AYInference 0.3.1 将 Chat/Responses 的缓存 token 细项及 DeepSeek hit/miss 规范化为
可选的 `cachedInputTokens` / `uncachedInputTokens`。缺失保持未知，明确的 0 保留；
只在输入总量已知时推导缺失补数，矛盾数据不作为命中统计。

加密 trace 的 `turns[].usage` 和 `reviews[].usage` 记录输入、输出、缓存命中与未命中。
后台生成档案增加 actor/review 的 profile 与 usage，保留旧统计字段。

授权本地接口 `GET /api/model-cache`、dashboard 的 `model_cache` 返回本次升级以来
按连接和用途累积的统计。QQ 通过原生插件事件汇入桌面统计；只含用量元数据，
不复制对白、记忆、图片、密钥或 provider 原始响应。

- `calls` 是程序调用尝试数，不等同于供应商最终计费笔数。
- `usage_reported_calls` 表示供应商提供了输入/输出用量的调用。
- `cache_reported_calls` 只统计 hit/miss 可确定的调用；没有报告的调用不会伪装成 0 命中。
- `cache_hit_ratio` 的分母仅为已报告缓存细项的输入，不包含输出。无分母时为 null。
- 统计不是历史账单回填，也不是费用计算器。供应商账单和后续真实 usage 才能确认
  实际命中率；本地回归中的命中数字仅为模拟数据。

验证入口：`AYInference_Tests`、`Hibernation_UnitTests`、`Hibernation_CachePipeline`，
以及现有上下文、峰谷策略、原生工具、双队列、独立审核和 NapCat 回归。

## 第二轮：嵌套证据、活动声明与有界追加

2026-10-28 的本机累计统计显示，普通对话约72.7%、QQ约59.5%、后台活动约54.4%，
活动审核约12.5%。这是当时样本，不代表固定能力或供应商承诺；低命中的活动审核
是优先检查对象。没有为获取这些数字重新发送私人对白或进行付费预热。

- 审核外层已经排序，但内层 `context` 和字符串形式的 `event_context` 仍被普通
  JSON 序列化恢复为字母顺序，动态身体/状态再次占据前部。现在对已授权证据的
  内层结构也使用对应布局；字段、来源、数组次序、实时数值和访问检查保留。
- QQ 追加通道身份、审核重建和交流偏好更新后继续使用同一种布局。QQ每条消息的
  编号和图片列表、共享阶段移到当前事件，system保留固定通道规则。权限仍由
  原通道身份和程序校验决定，不能通过正文自称取得权限。
- 活动参数声明按当前配置支持的能力保持稳定，不随物件是否存在、草稿容量或
  游戏是否进行而变化。`available_commands` 仍是当前可执行列表；后台返回及
  前台排队实际执行前仍按当前列表验证。声明可见不代表动作此刻可用。
- 同一轮已发送的工具回执在有界窗口内保持原文，后续只追加新回执。以前每次
  调用都缩写旧回执，会破坏刚建立的前缀。回执总量超过
  `max(16384, 4 * oldReceiptBytes)` 字节才重新压缩；记录 `receipt_rebases`，
  承认这次确有前缀重建。旧限制、来源和失败标记继续生效，不无限增长历史。

官方缓存依赖完全相同的前缀，支持请求边界落盘及公共前缀识别，且尽力而为：
https://api-docs.deepseek.com/zh-cn/guides/kv_cache/ 。例如缓存已建立后的49000个
重复输入token加1000个新token，比例为98%；这是负载构成的例子，不是所有请求
保证达到98%。增加无用历史或填充内容也能抬高比例，因此验收还必须看每次交互
的实际未命中输入、输出和费用。源码前缀比较只说明布局可复用，不冒充API命中率。

第二轮尚未实现跨所有对话的追加式会话重构。检索结果变化、历史窗口换段、图片
传递、撤销来源、修改人设/权限及必要的上下文重建仍可能中断复用；不得为维持
命中率保留已撤销的内容、伪造旧状态或延缓安全检查。

## 第三轮：跨轮的持久会话投影

桌面对话与QQ的普通用户消息现在维护独立的有界投影段。原始交谈、派生记忆与
人格/阶段的保存方式不变；投影保存在同一个加密记录库的私有
`ha.prompt-sessions` / `ha.prompt-segments` 中，不向角色检索接口或普通界面开放。

第一轮发送完整基线。以后保留此前已发送的消息前缀，只追加这轮的新来源视图、
当前事件和状态差异。状态使用RFC6902 patch，明确指向前一事件快照，支持null、
数组变化和字段删除；它不是把旧状态冒充为当前状态。过度零碎的差异会改为追加
完整快照。审核器由程序还原得到完整的当前事件，而不是自行猜测差异或审核旧输入。

成功且经过审核的轮次才保存一个新段，包括实际发送的工具链及最终获准回复。
段之间只保存引用，不在每轮复制整段旧历史。原始工具调用ID及结果顺序保留，
旧工具效果不重新执行。拒绝/重写、协议修复、图片输入或新建持续任务等复杂轮次
不发布可复用段；失败仍保留原流程的记录。图片像素不保存到文本会话投影中。

复用前逐条核对来源和版本，并核对访问策略、工作对白重建及阶段的版本。
模型、协议、工具声明、系统规则或相关配置变化会开启新段。中途发生权限撤销时，
后续模型调用与提案停止，已经完成的实际操作保留，不把撤销前的输入继续使用。
同轮经批准的记忆修订只更新其对应的来源版本凭据，修订请求与回执仍留在历史中；
其他来源版本变化不能借此绕过检查。
来源的“内容读取权限”与“仅供经历连续性判断的依据引用”分别保存和恢复；后者
不会因为进入投影而获得读取权限。旧实现元数据对白继续由原有排除规则过滤。

达到轮数/容量边界时，用本轮既有的有界检索结果、有效摘要和当前快照重建基线，
不额外调用模型做预热或凭空生成摘要。所有原始记录保留，可继续按权限检索。
配置关闭、完整模式、持续任务和后台活动规划仍可走原有装配路径。

管理页的“模型连接 → 上下文与调用精简”提供开关、容量和轮数设置，保存后生效：

```json
"contextControl": {
  "enabled": true,
  "preset": "balanced",
  "sessionProjection": true,
  "sessionBytes": 131072,
  "sessionMaxTurns": 16
}
```

容量为模型文本/调用数据的UTF-8字节窗口，取值16至512 KiB；轮数2至64。
节省模式默认64 KiB，均衡模式128 KiB，默认每段16轮。实际窗口还会为连接请求
大小、系统与工具声明留出余量；单轮过大则不保存该段，不截断本轮必要输入。
这个限制针对模型工作上下文，不是删除原始记录或保证数据库磁盘占用不再增长。

加密trace的`session_projection`记录基线/追加、重建原因、有效容量、初始事件
位置和保留来源引用，只展示元数据；不把本地共享前缀字节数当成供应商命中token。
跨进程检查包括前缀一致、重启、边界重建、撤销/恢复权限、审核读取当前状态、
中途遗忘、原文与加密保存，入口为`Hibernation_SessionProjection`；界面检查为
`tests/SessionProjectionForms.mjs`。官方用量仍须在部署后的真实调用中观察。
