# 桌面食材、背包与区域（第一版）

桌面小物保留原有的观察、种植、食用和摆放能力，新增可收集食材。
启用小食堂和桌面小物后，食材可以收进八格背包，或者明确选择收集后直接入库。
食堂原料、背包和仓库使用同一个引擎 Store；食堂制作直接使用仓库中的真实材料。
普通装饰不冒充食材，已有虚拟食物创作保留自己的来源。

## 代码归属与引擎复用

- BSimmer `src/supplies`：背包容量、采集、入库、取出、食用、批次来源与保鲜规则，
  以及区域规则验证和目标选择。小爱静态链接 `BSimmerSupplies::Rules`，运行包不依赖
  BSimmer 的安装目录或游戏存档。
- AliyatEngine `AYInventory::Core/Json`：唯一物品归属、World 到容器的拾取检查、
  原子批量转移、材料预留与消耗、已退役身份、带预留的版本化快照和 JSON 编解码。
- 小爱：桌面投影、区域内容、动画、模型工具、上层队列，以及现有加密存档接入。

没有新建另一套物品计数或存档文件。原始加密档案保持原有存储方式。
资源元数据和库存快照随整个插件状态一起保存。

## 区域与生成

默认窗边生成浆果、嫩叶、茶叶；种植角生成种子、小苹果；补给角出现面粉、清水、
黄油、牛奶和糖。每次补充最多放一个，受区域数量和桌面总量共同限制。
这是虚拟资源分布，并不表示面粉等原料在植物上生长。食材补充是环境进程，交谈或
角色暂时忙碌时仍会继续；实际采集动作仍服从输入打断和角色可用性。

管理页「桌面小物 → 食材区域」可设置名称、桌面百分比边界、允许食材、容量与
补充间隔，最多八个区域。区域重叠时列表靠前者优先。程序将落点限制在显示器工作区，
避开任务栏及显示器间空隙；没有可用交集时跳过生成，不挪到其他区域。
多显示器使用整个虚拟桌面的相对坐标。

`resourceSpawn` 控制食材生成；未配置时跟随原 `autoSpawn`。`autoSpawn` 仍控制普通
小物，食堂启用时不会额外随机生成旧的可食用模板。资源补充进度随存档保存，
暂停/关闭不补算离线产量，也不会每次重启立刻重新补齐。

桌面物件有淡入淡出；成功收集后淡出投影并进入容器。原区域记录在来源中，当前区域
按实际位置更新；搬动不会改变物品种类。食材到期会清理，存取不刷新期限。
原有基础原料补给继续保留，第一版不强制以采集代替所有补给。

## 上层工具与队列

- `habitat.gather`：可选 `region`、`ingredient_id`、`count`（1–8），程序逐件选目标、
  行走、检查与拾取；`destination` 为 `backpack` 或 `pantry`。
- 同一工具可用 `recipe_id` 按仓库实际可用原料计算缺料，默认直接入库；不与
  `ingredient_id` 混用。背包中的原料需显式入库，不会暗中移动。
- `habitat.act action=collect`：收集一个实际对象。鼠标点击可收集物也优先收进背包。
- `canteen.inventory`：按需查看背包/仓库中的实例、数量、来源与可食用性。
- `canteen.store`：一次入库整个背包，失败时整体保留。
- `canteen.move_supply`：在背包和仓库之间移动已有实例。
- `canteen.eat_supply`：直接吃指定实例的一份可食用物品，不能把面粉等原料当成成品吃。

角色现场和 `habitat.observe` 同时提供 `ingredient_id`、`can_eat` 和 `available_actions`。
食材权限以这些实际动作字段为准；外观模板保留自己的基础属性，例如面粉袋借用面包
图标，但可直接食用字段仍为 false。

自主队列支持 `gather`、`gather_for_recipe`、`store_supplies`、`eat_inventory`。
例如先 `gather_for_recipe(recipe_id=bread)`，再 `canteen_cook(recipe_id=bread)`。
一次意图不按每步移动调用模型；程序完成一件后重新寻找下一件。
accepted 只是开始，队列等待实际 gather 结束后才执行下一项。

目标不足会结束并保留已收集部分，不会凭空补资源。缺料未补齐时后续制作仍由引擎
真实库存检查拒绝。新输入、拖动、暂停、隐藏等会打断未来收集；已入包物品保留。
重启不重放旧移动队列。角色可以选择不采集，不要求每次收集后发言或形成长期记忆。

实际采集结果接入既有经历来源索引。整批采集只产生一条经历，附实际拾取的实例与来源；
空采集不产生已经采到的经历，部分成功不会证明整个意图已完成。从库存食用的结果可在
后续对话中检索，也可触发原有的 `item_consumed` 记忆任务。这些是程序事实，不自动
添加味觉、情绪或偏好。

## 一致性与验证

拾取由宿主在 owner 线程协调：锁定当前世界，核对距离、可用性和动作身份，再调用
食堂同一 Store 的引擎拾取事务。世界移除与库存发布期间禁止整包快照和插件重配置。
失败不会删除桌面物件；投影删除先在副本中准备，异常不会留下半个拾取结果。
完成后整包快照进入既有加密保存流程，沿用原有保存频率；不声称每次拾取都已立即
完成独立磁盘刷写。旧食堂存档补建空背包，不重置仓库或正在制作的材料预留。

检查入口：`Hibernation_FieldSupplies`、`Hibernation_FieldSuppliesProcess`、
`Hibernation_DesktopSuppliesForms`、`Hibernation_CanteenRules`、`Hibernation_CanteenProcess`，
以及 BSimmer 的 `Test_BSimmer_FieldSupplies`。进程检查使用合成对话、独立加密档案和
不可见测试桌面；不读取正式私人对话、不发送 QQ、不播放语音、不调用付费模型。

第一版没有背包图形窗口、仓库建筑、装饰收藏、资源点成熟/再生动画或完整种植收获系统。
原有种子种下后的芽苗不再作为原种子收进背包。
