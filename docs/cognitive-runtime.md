# 连续认知应用实验：阶段三至五

日期：2026-10-29。实现范围为可关闭的应用实验，不是意识实现或意识测量。
独立模拟器仍保留；正式应用继续使用现有工具协议、审核、WorkerHost、事件与加密存储。

0.8.0 候选追加 [自主作息](circadian-routine.md) 与加密因果轨迹；真实模型合成场景、
实际墙钟观察和未覆盖范围见 [八小时实测记录](continuity-eight-hour-results-20261030.md)。
本页描述应用接线，不以“完成实现”替代跨模型、长期人格或意识的实验结论。

## 阶段三：接入应用

- 桌面交谈和号主 QQ 共享一个工作状态；QQ 的操作仍由桌面后台串行执行。
  非号主、群聊等渠道不获得私有判断或恢复入口，原有电脑操作授权不因此扩大。
- 用户输入立即取消旧队列，保留尚未开始的部分，角色之后可选择继续或放下。
  短反应沿用现有互斥、冷却和前台优先机制，不在反应中另开认知模型调用。
- `activity.resume` 只接受当前恢复条目的版本。重新检查权限、来源、长期意图版本、
  插件、姿态、对象和队列容量，生成新操作 ID。旧队列原有期限也必须仍有效。
  正在执行的部分仅显示为已中断、需要重新判断，不复制为重试命令。
- 保存或重启时可保留未开始的打算。重启不自动执行、补算离线活动或重放未知写操作。
  同一批打断去重；一次恢复后不能再恢复第二次；主动取消会放下现有恢复条目。
- 实际动作完成仍使用原来的匹配令牌、工具回执或真实姿态持续时间。
  accepted、排队、动画播放和说出承诺都不等于动作已经完成。

## 阶段四：自身事实、判断与档案分开

| 内容 | 权威位置 | 写入方式 |
| --- | --- | --- |
| 当前身体、姿态和位置 | RoleState、body 与插件现场 | 程序连续更新；模型不能直接覆盖数值 |
| 真实活动和结果 | 现有活动队列、事件和原始档案 | 原有动作执行器与实际回执 |
| 当前注意、打断打算、预期 | 加密 `ha.mind/working` | 有界程序策略与明确选择 |
| 暂定判断 | 加密 `ha.interpretation` 与历史版本 | `mind.interpret`，最多 32 条，每条最多 256 次版本 |
| 经历性偏好与长期意图 | 现有 `ha.personal` | `self.notice`、独立经历锚点和原有审核 |

`mind.observe` 读取有界私有视图；`mind.attend` 按版本选择一个当前候选。
`mind.interpret` 必须引用本轮真实可用交谈或经历，置信度仅为 uncertain/tentative。
更正产生新版本，撤回保留历史；来源隐藏或版本不一致时不再提供该判断。
判断和工作状态不作为新的原始经历，不因查询而强化偏好，也不自动更改人设或阶段。
更换模型只重建模型上下文，这些程序拥有的状态继续存在。

预期记录排队、执行、完成、中断、失败或未知等实际状态。取消后的迟到效果单独记录，
不把“打算已取消”改写为“打算完成”，也不抹掉已经发生的写入。
运行条件与角色身体分别表示，不把余额、声音通道或网络故障解释为痛苦或依赖升级。

## 阶段五：有限注意、按需观察与跨会话活动

- 最多六个注意候选，一个主要焦点，默认驻留五秒并设切换差值；前台输入优先。
  候选来自实际活动、身体需要、未完成打算和眼前可观察的小物。没有事情时允许安静。
- 工作时钟仅在进程活跃且未暂停时推进；长时间卡顿最多计一秒，重启不补计离线时间。
- 对小物的观察建议只给已存在对象的工具入口，不声称已经看到或理解。
  沿用 habitat/阅读/创作等现有工具，不新增屏幕监控、视频解码或全屏采样系统。
- 自主规划对已实际观察的同一内容设置默认两分钟冷却；对象阶段或作品版本变化可再观察。
  书面材料按条目、语言、正文范围区分。前台明确要求的重新查看不受此后台冷却拦截。
  冷却只在真实观察完成后记入，不因模型提出计划或查询状态而刷新。
- 经验性偏好复用原有真实来源与经历锚点机制。模型可以保留、改变或放下关注；
  程序不根据注意分数直接制造偏好，不为每个动作自动生成日记或情绪评分。
- 挂起条目最多三个、实际结果最多十六个、观察冷却记录最多三十二个。
  工作状态总量有上限；容量不足优先舍弃旧工作缓存，原始档案不删除。

这些机制不增加常驻连接或必需的额外模型轮次。后台观察与活动继续使用现有日预算、
峰谷策略、暂停、离线和前台保留额度；所有新增工具可被现有受限 skill 进一步收窄。

## 开关与回退

管理页“模型连接 → 调用额度 → 连续注意与打算（实验）”保存后生效。
配置对应：

```json
"cognition": {
  "enabled": false,
  "attention": true,
  "observations": true,
  "dwellMs": 5000,
  "resumeMinutes": 15,
  "observationCooldownMs": 120000
}
```

旧配置和示例默认关闭；关闭后恢复原工具与调度流程，保留已经加密保存的历史。
管理状态 `/api/mind/status` 只有计数和可用性，不提供判断或记忆正文。
提供给模型的工作视图另外限制为 8 KiB；待续草稿正文保留在加密程序状态中，视图只给
动作、目的和内容已保留的标记，不为续接重复发送整段草稿。QQ 原生来源栅栏在进入
模型前单独提取，不作为对白内容。撤回判断留下编号和版本墓碑，避免误当成仍有效。
文件损坏或未来版本不支持时保留原件并禁用相关状态，不以空状态覆盖原件。
原始数据、密钥、工作区和构建位置仍独立配置。

## 验证和解释范围

`Hibernation_ContinuityMindTests` 检查驻留对照、前台抢占、版本栅栏、挂起、暂停、重启、
迟到结果、观察冷却、渠道隔离、格式兼容性与派生状态不成为原始经历。
`tests/ContinuityMind.ps1` 在独立桌面、独立加密存档和本地模型模拟服务中检查实际应用。
`RuntimeControlForms.mjs` 检查开关、时间单位、热保存及私密内容不进入管理诊断。
既有偏好、意图队列、前台优先、QQ、预算和模型上下文检查继续作为回归。

确定性对照可以证明减少候选抖动和重复观察请求，不能证明语言更自然或存在主观体验。
跨天连续性、真实模型自由选择的质量、实际 token 与延迟收益需要后续有界实测；
不把本地模拟请求次数当作供应商账单，也不将机制计数合成为“意识分数”。

构建入口：`scripts/Build.ps1`，主目录 `out/build`。
独立验证入口 `Hibernation_ContinuityHost` 与正式桌面入口使用相同源文件和核心库，
便于在主程序仍运行时验证新核心，不会连接生产档案。
完整候选包另用独立临时构建验证所有插件；不以旧运行目录里尚未重新链接的插件
冒充已验证的新插件。正式实例更新与源码／候选包验证的状态分别记录。
