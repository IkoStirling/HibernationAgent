# 自己的一小段时间

这层逻辑让已有打算能够进入一次完整工具会话。它复用引擎的持久任务、互斥、抢占和预算，不另建任务引擎，也不改人格、发展阶段或原始记忆。

## 用户设置

桌面小角色必须启用且开启 `autonomousMode`。管理页可以单独关闭 `autonomyPursuitEnabled`，继续保留原来的有限动作规划。

| 设置 | 默认 | 范围 | 含义 |
| --- | --- | --- | --- |
| `autonomyPursuitEnabled` | true | 布尔 | 是否允许接续已有打算 |
| `autonomyPursuitCooldownSeconds` | 120 | 10～3600秒 | 两次申请的最短间隔；不是强制执行频率 |
| `autonomyPursuitMaxSeconds` | 90 | 5～100秒 | 包括模型、审核和工具等待的一次最长时段 |

后台总额、作息、离开预留、暂停和插件开关继续生效。用户活跃时预留至少约10%输入和少量调用；离开时保留原来的约40%输入预留。使用量是调用后记账，预留不是尚未发生费用的硬锁定。没有重置额度或新增一份预算。

阅读还需启用阅读角原有 `autonomousReading`；仅安装插件不会授予自行联网阅读的权限。现有屏幕观察开关及冷却继续约束后台的全屏截图。

管理页“运行状态与活动”显示自己的活动为何暂缓：休息、输入中、暂停、预算预留、冷却或上一段正在收尾；诊断导出只保留这些状态，不含打算内容。休息或用户仍在输入时不会受理90秒的短时机会，避免尚未开始便在等待中到期。

## 打算、机会、实际结果

1. `self.notice` 留下有来源的 `intention`，沿用 `ha.personal` 及语义版本。
2. 背景规划可以选择 `pursue_intention`，绑定实际存在且可访问的打算及版本，选择一个可用领域。也可不选任何行动。
3. 程序再次核对来源、版本、领域、预算和间隔，排入固定槽位 `autonomy.personal-pursuit`，任务类型 `role.personal-pursuit`。
4. 角色按本次现场使用领域工具。真正的工具结果逐次进入原有档案，并与这次尝试关联。
5. 这段时间结束后保存考虑、行动或被打断的结果。局部完成不自动关闭整个打算，不强制说话、写日记或向用户汇报。

普通持续长任务仍使用原有系统。用户新输入优先；短时独处被抢占或程序重启后保留已发生结果，结束那份旧模型计划，之后重新选择。不会自动重放已执行步骤。程序持有数据目录排他锁时，仅对上一实例的该专用槽位调用引擎带令牌栅栏的 `finish`，释放旧互斥租约。

`self.reconsider` 可以搁置或重新拿起。`soon`、`later`、`much_later` 对应约5分钟、30分钟、2小时；期限结束只恢复可考虑性。决定需有真实来源并改变语义版本，因此旧版本排队动作失效。关闭、来源撤销和领域关闭同样会阻止旧计划继续。

## 工具范围

所有领域都有有限的自身、身体、状态及记忆工具；底层权限和来源验证继续执行。

| 领域 | 具体工具范围 |
| --- | --- |
| kitchen | 食堂工具，桌面采集、观察和物件动作 |
| reading | 阅读角工具，工作室读取／写作；需自主阅读许可 |
| creative | 工作室、像素工具及工作区列表／读取／查看图片 |
| desktop | 小组件、桌面物件、背包、天气及获准的截图 |

此入口不提供外部发信、启动应用、导师执行、激活Skill或创建另一条长任务的通道。`capabilities.list` 与实际调用均受本领域过滤，换领域需要下一次机会。普通前台工具能力不因此缩减。

## 记忆与上下文

原始记录持续保存在加密档案；本次只装配有限内容。已有打算的全部来源仍逐项核权，最近至多4个依据固定装入原文，其他依据可按原检索工具读取。主动选择某个旧打算后，优先给出它的完整私记。

背景最多提供8条个人关注：近期为主，留少量位置轮换较久未提供但仍可访问的旧打算。轮换只记录“提供过上下文”，不会增加兴趣、偏好、经历次数或自动执行动作。

料理按实际 `batch_id` 关联受理、做好、端出、食用或中断。派生尝试同时依赖原始受理和实际结果，撤销其中来源会隐藏相应关联。原始档案不删除。身体视图只展示仍存在的当前采集／料理，旧结果仍留在历史中。

当前工作表最多保留24条活跃关注、128条关注索引；到达上限会明确拒绝新增，最终回复成功不等于新增成功。关闭关注可以释放活跃位置，原始经历及版本继续保存；本轮未改造长期关注容量或原始记忆架构。

## 规划与恢复边界

模型阅读的格式说明使用本地Schema引用去掉重复声明；提供商结构化输出和程序校验仍用原内联Schema。声明容量固定为协议上限，实际剩余槽位和当前动作另行准入。

初稿格式、动作或同批版本存在冲突时，最多提供一次修正机会。整批最终有效后才审核和执行，不默默丢掉部分非法动作。同批更新一个打算又绑定其旧版本的动作会被拒绝。

专用任务类型避免旧版本把它误认成普通独处会话。旧主机对未知类型的精确 `handler unavailable` 失败曾以 `turn.completed` 归档；重新升级时保留这个分支的原通道身份，普通自主结果仍为 `solitude.completed`。复用引擎的严格事件幂等，不改写既有事件，也不吞掉其他冲突。正式升级先暂停，关闭后台并校验加密主档和QQ子档备份，再暂停启动新版本核验。回退程序时保留暂停，不能据此宣称任意旧二进制可无损降级。

## 验证范围与仍有限制

`IntentionLife`、`IntentionEffects`、`IntentionDeadline`、`IntentionBody`、`IntentionFocus`、`IntentionRestart`、`PlanningPrefix`、`PlanningRepair` 覆盖版本、来源、领域、异步结果、时限、身体推进、旧打算、重启与修正；缓存、QQ共用上下文、持续任务、作息和置顶另做回归。

真实实验使用独立合成存档。已有自行接续写作并在后来对白记得具体内容的成功片段；缺料生活场景用于定位自身思考阻塞采集的问题，不能当成完整料理闭环成功证据。自然度仍受模型、历史和预算影响，不保证每次主动行动或消除所有机械表达。本轮不采用禁词替换，也没有重训练模型。

动作与PixelLab制作入口见 [角色动作表](character-action-catalog.md)，本层没有新增独立动画。实际实验、失败修正和交付结果见 [工作记录](autonomous-life-worklog.md)。
