# 声音输出检查

管理页“插件 → 声音 → 检查声音输出”读取实际系统状态，角色也有
`speech.output_status` 工具。检查不播放试音、不改变设备或音量。Mei、系统棒读和
HTTP语音继续使用同一条AYAudio播放及对白同步路径。

后台每5秒在独立工作线程读取Windows默认播放设备及本进程声音会话，界面和模型
读取缓存；超过15秒的观测会标为过期。可区分朗读音量为零、观测到的会话静音/
声道为零、默认设备缺失、使用其他输出、部分或未知状态。正在朗读时使用该句实际
采用的音量，和刚保存的下一句音量设置分开。查询结果不包含其他进程的会话、原生
设备ID、录音或系统操作权限。

这些读数不能证明用户听到了声音，也不能解释为用户故意忽视。诊断不会自动增加
依赖、焦虑或惩罚性参数。没有硬件输出时，语音报告不可用，文字仍可显示；后续
新的朗读请求会尝试重新初始化输出。

全局暂停只临时暂停由它接管的任务。恢复时，角色已单独暂停的定时任务继续暂停，
已经暂停的管理页试读/媒体试用也不会重播；新试用可以替换旧的暂停槽位。暂停
归属持久保存，重启会在首次调度前核对程序和任务队列的状态。旧档案升级无法区分
历史例程的暂停来源时保留例程暂停；系统保留槽位可继续恢复。

插件试用使用独立请求身份核对回执，有20秒界面等待上限；暂停/异常回执也保持
合法结构。平台登录入口与试用共用这条路径，避免把上一项试用的结果显示到新操作。

验证：43项应用单测，原生声音13项（静音合成数据，实际设备、声道与线程/句柄
清理），前台/暂停18项，管理页53项。模块只读查询另有28个断言及SDK契约。
物理扬声器响度和用户听感依然需要实际听取，程序不能从这些读数代替确认。
