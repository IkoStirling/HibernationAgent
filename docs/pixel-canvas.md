# 像素创作台

像素创作台是独立可选插件。小爱可以通过工具绘制作品、做简单逐帧动画、查看作品数据并继续修改；操作者可以在 Dashboard 的插件页使用同一套编辑与保存能力。作品属于刻意创作的草稿，与私人记忆、人设和真实外部经历分开。

## 开始使用

构建并安装 `pixel-canvas` 后，在插件页启用“像素创作台”，点击“保存插件设置”。编辑器不会擅自保存其他插件配置。点击“刷新作品列表”可以读取已有作品；新建时指定编号、名称和画布尺寸。编号使用小写字母、数字、下划线或短横线，最长48字符。

画布宽、高分别支持16、32、64像素。每个像素存储调色板索引，索引0代表透明。颜色按钮显示索引，选中的颜色有边框。可用RGB拾色器、RGBA十六进制和不透明度准备新色值；点击“应用到所选颜色”才保存。修改已有色值会更新所有帧中使用该索引的像素，“添加为新颜色”保留原有颜色并追加一项。调色板最多32色，颜色0始终完全透明，不支持删除或重排。画笔、透明橡皮、直线、空心与实心矩形、连通填充可通过鼠标操作；一次笔画提交为一个有界批次，不会每移动一个像素就发起一次模型请求。坐标输入和画布方向键、空格也可绘制指定像素；画布聚焦时Ctrl+Z撤销、Ctrl+Shift+Z重做，Esc取消未完成笔画。调色板支持方向键、Home和End选择颜色。

修改成功后立即保存草稿并增加版本号。“撤销上次修改”恢复上一份内容，同时产生新版本；撤销与重做合计最多保留8份快照，新绘图、调色或帧编辑会清空重做队列。小爱与编辑页面可能同时修改同一作品；旧版本提交会被拒绝，页面要求重新读取，不会盲目重试覆盖另一方的新内容。编辑器缓存按后台确认的实际草稿工作区区分；切换工作区会清空旧预览，即使另一个工作区有同编号、同版本的作品，也不能沿用旧内容修改它。每次提交另带工作区前置条件，防止检查状态后、排队执行前恰好切换工作区。失败笔画回到最后确认保存的画面，不把未保存预览显示成成功。

## 内置示例草稿

第一次使用时，可在“内置示例草稿”选择小灯（1帧）、嫩芽（2帧）或闪烁星（3帧）。先填写一个未占用的新作品编号和名称，再点击“创建示例草稿”。选择示例或打开页面都不会自动创建；这些是应用提供的可编辑起点，不是小爱自主创作的作品。

示例固定为16×16像素，并带有自己的调色板与帧时长。创建后仍使用普通绘图、调色、撤销和导出功能。每一步都等待程序实际回执并使用返回的新版本；编号已存在时，不继续执行后续步骤，也不覆盖旧作品。如果中途失败，已经完成的部分保留为草稿，页面说明当前确认保存的编号与版本，剩余步骤不自动重试。

## 帧与导出

每件作品最多8帧。可新增空白帧、复制、删除或分别设置50至5000毫秒的帧时长，至少保留一帧。预览使用像素缩放，关闭或隐藏页面时停止；系统启用减少动态效果时使用逐帧查看。

“导出当前帧 PNG”输出原像素尺寸的透明图片。“导出序列帧图集”输出横向排列的完整图集及动画说明。导出位置由插件在作品工作区内确定，模型与页面不能指定任意外部写入路径。作品编号和版本可用于后续追溯；导出不自动替换桌面角色素材。

“放到桌面”请求展示这件作品。请求被接受与窗口实际出现是两个状态；页面不会把排队成功说成已经显示。收起窗口保留作品草稿。桌面展示能力依赖当前宿主是否允许创建桌面窗口。启用“启动时恢复上次实际展示的作品”后，只恢复同一工作区、同一作品版本、上次已实际显示的作品；隐藏、失败或仅排队的展示请求不会恢复。重启从第1帧开始，不补播离线时段。

## 角色工具

插件启用后，角色可使用 `pixel.list`、`pixel.create`、`pixel.read`、`pixel.edit`、`pixel.palette`、`pixel.frame`、`pixel.undo`、`pixel.redo`、`pixel.export`、`pixel.preview`、`pixel.show`。管理页的原生编辑接口返回完整作品，包括各帧像素索引，供画布编辑。角色收到的回执使用有界结构：作品编号、尺寸、调色板、帧数、帧时长和当前版本；不会把全量像素网格反复装配到模型上下文。需要查看画面时使用`pixel.preview`生成实际PNG，并通过已支持识图的连接附图；没有识图或没有确认投递时，不能把“生成预览”说成“模型已看到或理解”。编辑需要 `expected_revision`；只有程序确认保存或导出成功后，才可以将它表述为已完成的创作。

这些工具提供像素操作能力，并不保证模型具有专业美术能力。小爱可以保留不满意的草稿、以后再改，也可以不创作；应用不强制生成作品或公开日记。

## 验证入口

`tests/PixelCanvasForms.mjs`使用独立合成档案和实际构建的插件，检查页面新建、鼠标绘制、调色板索引、撤销、帧编辑、动态预览、PNG与图集文件、并发版本冲突及重新读取。默认不调用真实模型，不读取正式私人对话。实际运行结果应以本轮工作记录与测试输出为准。

在项目根目录、已有本轮候选构建的机器上，可复跑插件的定向门禁：

```powershell
ctest --test-dir out/pixel-canvas-isolated -C Release --output-on-failure -R "^Hibernation_(PixelCanvas|PixelSurface|PixelCanvasModel|PixelCanvasProcess|PixelCanvasForms|PixelCanvasScene|PixelCanvasRestore|PixelPreviewLauncher)$"
```

这条命令用于复现像素插件相关检查，不包含本轮另外执行的完整单元、原生工具、角色连续性或LoRA回归。测试使用配置构建时绑定的冻结资源；如果自行重建，应按 `scripts/Build.ps1` 生成匹配的构建与资源。


2026-10-28在Windows/Chrome上，实际插件浏览器检查最终通过59项。范围包括禁用及未保存配置、鼠标与键盘绘图、捕获取消、撤销与重做、RGBA颜色与透明度、32色和8帧边界、真实PNG、三种示例的确切像素及帧时长、占用编号拒绝、中断后保留部分草稿、示例继续编辑，以及两个工作区同编号同版本时的缓存隔离与提交竞态保护。600像素页面、减少动态和隐藏停止亦已验证，并人工检查了最终宽屏、窄屏示例及8帧截图。新示例的中断回归曾发现选中帧早于创建回执切换，导致失败提示绘制越界；修复后单独重新运行浏览器组，59项全部通过。其他后端门禁的实际批次和结果见本轮工作记录。测试使用独立合成工作区及宿主副本，不锁住构建EXE；无付费API调用，也不证明模型创作质量。


## 本机独立预览

完成候选构建后，可双击项目根目录的 `PreviewPixelCanvas.cmd`。本轮候选目录为 `out/pixel-canvas-isolated`，资源由其 `pixel-canvas-candidate.json` 指向经过验证的冻结源码。首次预览使用新的 `out/pixel-canvas-preview`，只启用离线演示和像素插件，关闭电脑工具与远端同步；不导入正式档案或密钥。

进入管理页的“可选插件”，展开“像素创作台”，刷新作品列表即可打开本轮另存的“开发演示：月下的小灯”（三帧，可编辑）。这是开发会话通过真实工具制作的演示作品，不是小爱私人记忆或自主创作的证明。内置灯、嫩芽和星星模板同样是明确标记的示例。

可通过 `scripts/StartPixelCanvasPreview.ps1 -CheckConfig` 只检查配置，通过 `-Stop` 停止预览。需要改构建与资源目录时使用对应参数；已有预览若绑定另一套程序会拒绝混用，应使用原版本或新的 `WorkspaceRoot`。预览保留用户后来配置的模型选择，但要求存档、草稿和素材留在自己的目录中。正常应用仍使用原启动入口和配置。

## 两种实际使用方式

不配置模型也可以使用管理页：打开“开发演示：月下的小灯”，更改颜色或一个像素，观察版本增加，再撤销或重做；点击“放到桌面”，等待实际显示提示。右键作品可以收起，随后仍能从管理页重新展示。当前桌面同时展示一件作品，展示另一件会切换内容，不会生成无限多个窗口。

让小爱自主创作时，需要在这个独立预览的管理页另外配置真实模型连接。启动器不会复制正式实例的密钥与记忆。可以先给一个有界请求，例如：“画一盏你愿意放在桌边的小灯，16×16就好。先做一帧，满意了再放到桌面。”这只是使用建议，不能保证模型第一次就画好。后续可以要求“把刚才的小灯改成两个明暗交替的帧，先保留原稿”，由模型根据实际作品编号和当前版本继续编辑。若希望它根据画面修正，连接还需真实支持并启用图片输入；仅支持文字的连接仍能下达绘图命令。

工具按“新建或读取 → 使用当前版本编辑 → 按需预览 → 展示或导出”衔接。不能硬编码某个版本号，也不应在收到版本冲突后原样反复调用。每次成功修改都返回新版本，撤销和重做也一样。演示使用的是开发人员制作的起点，不能把示例标题或默认模板当作角色自己的审美、记忆或创作经历。

## 常见拒绝与恢复

| 情况 | 处理 |
|---|---|
| `pixel_revision_conflict`、页面提示版本过期 | 重新读取作品，确认另一方的实际修改后再编辑；不强行覆盖。 |
| `workspace_changed` | 刷新工作区与作品列表，重新选择当前工作区的作品。旧预览不能直接提交到新位置。 |
| `pixel_document_exists` | 选择新编号，或明确读取并编辑已有作品；新建不覆盖旧稿。 |
| `pixel_document_limit` | 已达到配置中的作品数量上限。先检查草稿目录；损坏但占位的文件也算名额，不会自动删除原稿。 |
| `runtime_paused`、作品尚未实际出现 | 确认后台已恢复且允许桌面窗口，再发出新的展示请求；暂停前排队的请求不会在恢复后补播。 |
| `pixel_export_exists` | 相同版本的导出文件已存在且内容不同，程序拒绝覆盖。检查旧文件，或继续编辑生成新版本后导出。 |
| 预览“已生成”，模型仍表示看不到 | 检查连接是否支持图片以及图片投递是否成功。生成PNG和模型实际收到图片是两件事。 |

现有图集说明是 `pixel_sequence` 格式，暂未提供GIF、Spine或桌面角色包的自动转换。作品草稿也不是加密私人记忆：它们位于自己的受限草稿工作区，适合之后继续修改或人工取用。
