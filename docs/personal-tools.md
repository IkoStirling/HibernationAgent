# 个人关注、创作与视觉输入

固定人格、发展阶段、连续生理/交流数值、个人关注和长期记忆分别管理。个人关注不重写人设，也不预设新的关系。模型可以留下自己的兴趣、偏好与小意图；程序负责来源、数量、版本、重复强化和渐变，不把一个数值映射成固定对白。

## 个人关注

`self.observe` 返回近期可访问的关注；`self.notice` 提交 topic/note/stance 和真实 source_ids，新记录 expected_revision=0，更新使用已有语义版本。interest 对应 curious，preference 对应 like/avoid，intention 对应 want。记录的 kind/topic 保持身份，改变关注点应使用新记录。程序最多保留24个活跃项、128个工作索引；每项最多12段近期证据，数据库保留所有原始版本。

同一来源组合不会重复强化或覆盖原说明。leaning、target_leaning、evidence_count、familiarity 等不是模型可写参数；偏好随实际运行时间向有限目标移动，暂停与重启会重置计时基准，避免离线虚构巩固过程。后台数值持久化与模型编辑的语义版本分开，时钟更新不会造成编辑版本冲突。

`self.close` 可 completed / abandoned / released。完成只用于意图，必须有实际动作结果；只读一下自己的意图或收到一个请求不算完成。改变主意和暂时放下保留说明与依据，不删除历史。关注出现在对话和自主计划上下文中，不要求每次提起或保存。其原始正文加密存储，不进入聊天界面。

开启reflectOnActivities后，独处也可以使用已完成的阅读/创作来源提出self.notice，无需用户先提出一个问题。这是有界的新经历考虑机会，不是应用替角色指定兴趣：允许无更新，已考虑来源去重、自动间隔至少15分钟、访问过滤和前台优先继续生效。详见[身体与日常表达](embodied-dialogue.md)。

## 个人创作角插件

atelier 是独立可选插件，没有桌面窗口或小角色依赖。角色可以通过 list/read/write 留下短笺、故事、观察作品或图画构思，使用 draft / finished / set_aside 进度。后续可以读取和续写，而非每次只从当轮开始。

作品存放于允许草稿根的 atelier/ 子目录，每件作品一个有版本的 JSON 草稿。它们是刻意创作的作品，与内部记忆分开；作品内容不提升为发生过的外部经历，也不写入小说正式设定。程序校验相对身份、内容预算、乐观版本和作品数量，已有损坏文件不作为新作品覆盖。关闭插件保留作品。快照保留少量标题、进度和最多两件草稿的有界末尾节选，文件扫描有缓存，避免高频身体状态采样反复遍历所有草稿。

## 图片输入

连接的 supportsVision 是显式能力声明。工具可以返回电视当前帧、已允许的截图，或由 workspace.view_image 读取草稿/素材根中的图片。文件最多8MiB，实际解码、检查像素预算后，按最长边960像素转为JPEG；透明部分合成白底，动画只读取首帧。任意路径、私有档案和网页图片下载不由此工具开放。

实际图片以模型图像内容块发送；工具文字只保留 source_id、尺寸和附图状态。最多四张最新图片，旧上下文图片清除，原始观察按来源与版本留在加密档案。审核连接启用视觉时接收同一最新图片；未启用时明确其证据限制。会播放声音不等于能理解声音。

取到图片、准备请求和服务接受附图请求分别记录。额度在取图后耗尽时，来源仍保存，但投递状态只是prepared；不能据此说模型已收到。服务明确拒绝和无法确认的传输结果分别记为rejected/unknown。后续装配遇到缺失回执时保留不确定性，不替原始档案补造成功或失败。acknowledged只表示附图请求获得成功HTTP响应，不证明模型理解正确。

实际请求结果另存加密投递凭据，和原始观察分开。沉默回看或调用随后被打断，已经发生的投递仍可追溯；后续失败不会抹掉此前确认交付的事实。回看可以更新该来源在近期上下文的相关性，原始观察的时间、版本和内容不变。

工作区文本读取只处理无NUL的有效UTF-8。误把PNG等二进制当文本时返回workspace_not_text，交由模型选择图片/视频工具，不把原始字节塞进JSON导致整轮异常。文本与目录观察带实际source_mount/source_path；分页仍按字节并对齐UTF-8边界，不自动改编码或改写源文件。

2026-10-27 核查的官方 DeepSeek 文档确认 deepseek-flash 通过 Chat Completions 与 Responses 接受图片；当前未配置已验证的原生音频输入。应用录音和音频转文字保留为后续任务。

## 实验

tools/DialogueEvaluation.ps1 默认 Mock，显式 -Live 才会调用已配置服务。每个场景、审核条件与历史条件使用独立新加密档案，保护凭据只临时复制且在 finally 中清理，不读取正式私人记忆。支持 empty / short-history 对照；后者由独立的两轮交谈形成，报告中将种子轮单独标记，不把它当作完全相同历史的统计实验。

输出包含实际回复、审核裁决、结构修复、用量及耗时。完整 fenced JSON 仅在本地完整结构校验后规范化。对于非严格 Schema 连接，在启用独立审核时，可将有限纯对白包装为 reply-only 候选，再经过完整结构与审核检查；它不会生成任何动作。JSON标量、JSON/代码外夹解释、错误类型、未知字段与越权工具不能据此放行。流式候选不显示、不朗读、不执行；只有经过最终应用校验和审核的内容进入展示。

后续轮次最多携带四条近期操作的简短凭据，包括来源、发生时间、动作结果和图片是否真正交给了模型。原始图片、正文和工具日志不重复装配。意图回执保持 tool_intent，不能当作已完成；访问策略过滤被隐藏的来源。这样能记得刚才确实看过图片或写过作品，同时避免只根据过去一句自述确认操作。

具体观察与动作的近期索引独立于聊天回复：成功工具即保存真实来源，之后沉默、被打断或模型请求失败，不会令实际已经完成的效果消失；也不因此把整轮任务标成成功。索引最多24项，日常上下文仍最多四条，重启保留并继续检查来源访问。内部状态快照和高频诊断不进入这一索引；旧记录通过原有追溯路径读取，不批量改写档案。

`observation.revisit` 只接受本轮上下文已有授权的具体观察来源，检查类型、原版本与当前可访问性。可以回看当时的素材图片、电视帧、文本、目录、阅读资料或作品原文，不读取已改变的外部文件，不枚举档案，不回放旧内部状态。原始时间和“过去观察”性质保留；图片需要当前连接支持视觉才实际附上。回看复用原来源，不把旧内容标成现在新看到，也不修改原记录。来源被隐藏后，即使重放已有工具调用也重新验证权限。
