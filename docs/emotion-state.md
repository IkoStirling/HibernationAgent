# 连续计算情感与虚拟欲望

这是虚拟角色的程序状态，不是意识或主观体验的证明，也不把“七情六欲”当成固定的
医学、心理学或生物学分类。本模块提供七类可混合的情感倾向和六类虚拟欲望；实际
表现仍取决于当下交流、角色选择、工具权限与真实经历。

情感 ID：`joy` 喜悦、`anger` 愤怒、`sadness` 悲伤、`worry` 担忧、`affection` 喜爱、
`disgust` 厌恶、`surprise` 惊讶。欲望 ID：`rest` 休息、`explore` 探索、`company` 陪伴、
`express` 表达、`play` 玩耍、`replenish` 补给。它们不包含性欲，不预设恋爱关系，
也不因用户离开而累积依恋、愤怒或惩罚。

## 刺激和更新

宿主先检查来源是否属于本次获准上下文，以及该来源是否真实、仍可访问和适合当前
感受提案。核心不读取记忆或决定来源权限；空 ID、错误类型和无效 UTF-8 不能绕过
外层授权。

`RoleState::stimulate(stimulus, sourceId, now, issue)` 接受例如：

```json
{
  "emotions": {"anger": 0.7, "sadness": 0.2},
  "desires": {"express": 0.4, "company": -0.2}
}
```

这表示刺激的方向和强弱，不是将实际愤怒设为 0.7。每类最多三个字段，每个值在
[-1,1]，绝对值合计至多 3；空刺激、全零、未知字段、直接 `set`／`target`、布尔值、
非有限数值均被拒绝。程序只更新有界 latent drive，调用本身不改变实际情感、欲望、
心情、身体活动或已有 appraisal。

实际值只在正常活跃 tick 中变化。每 tick 至多推进 0.25 秒；情感每秒最多变化
0.01（惊讶为 0.025），欲望每秒最多变化 0.004。刺激按活跃时间指数衰减，惊讶比
其他情感消退更快。程序目标和更新结果都在 [0,1] 内，不通过一次模型输出跳变。
这些参数是可检验的工程选择，不是科学测量得到的情绪公式。

最近 128 个已接受来源用于去重；同一来源即使更改参数也不能再累加。不同来源之间
至少隔五秒真实活跃推进。暂停、挂起或关闭程序不能通过墙钟流逝绕过这个冷却。
这是一份有界去重账本，不是永久保存全部来源的替代品；原始来源仍在独立加密档案
中保留，宿主始终负责来源时效和授权。

## 与既有状态的关系

旧版的 energy、openness、mood、attention、willingness、social load 和活动状态保留。
情感初始全中性，不根据旧 mood 编造过去的喜怒。新的真实情感只逐渐影响既有
target mood 和 willingness，最终仍经原速度限制和模式迟滞处理。它不会直接选择
活动、安排工具、关闭权限、说话或拒绝。

欲望的平缓基准使用既有精力、开放程度、注意和社交负荷。例如低精力可提高休息
倾向、较高社交负荷可降低陪伴倾向。这不是诊断真实身体饥饿；补给只是虚拟角色
偏好，不证明桌面有食物、库存足够或某项操作已经完成。

生气可以体现为简短反驳、拒绝、沉默，或不带脏字的克制冷讽。模块仅在渐进强度
达到阈值后提供冷讽许可，不强制每句挖苦、不生成辱骂脚本、不要求羞辱他人，也不
把喜爱自动解释为恋爱或占有。没有规定每轮回复必须表情绪或朗读数值。

## 存档和模型边界

`RoleState.snapshot().version` 为 4，新增 `affect` 的 v1 子结构。旧 v1／v2／v3 存档
仍可恢复，已有数值保持原样，新的情感层从中性开始。暂停和跨进程恢复都保存实际
情感、驱动、活跃时钟和去重账本，不补算离线时间。

v4 必须带完整有效的 `affect`，缺失或损坏时整体拒绝；全部 RoleState 字段验证成功后
才替换实时状态。坏存档不能部分覆盖精力等旧值，也不能清空来源去重保护。
拖动回复与活动候选的缓存键增加 `dominant_emotion`、`dominant_desire` 两个粗分类及
`may_use_dry_irony` 布尔许可，因此喜悦仍占主导时出现明显怒气也会使旧候选失效；
不会把逐帧浮点值、驱动、来源账本或活跃时钟放进键。拖动候选生成使用公共情感投影。

旧 0.8 程序只接受 RoleState v1／v2／v3，不能直接读取 v4。保留新存档和全部新记忆，
部署失败时不能用旧备份覆盖新数据，也不能仅把版本号改为 3 冒充无损降级。确需旧功能
回退时，须单独验证能读取 v4 并在后续保存时保留情感子结构的兼容构建；本次未实现或
验证此兼容构建，因此普通 0.8 二进制不构成可用的数据回退方案。

完整 `affect` 含 `emotion_drive`、`desire_drive`、`sources` 和活跃时钟，属于加密持久
状态，不应原封不动交给角色或审核模型。`RoleState::emotionalContext()` 仅提供实际
`emotions`／`desires`、粗略的主导倾向和行为许可。宿主必须在 `modelLifeState`、工具
回执和审核输入中使用该投影；界面继续以对话为主，不展示记忆或内部数值。

刺激失败码：`invalid_emotion_stimulus`、`emotion_source_already_used`、
`emotion_stimulus_cooldown`。所有拒绝保持原情感状态；不能把未接受的刺激当成已经
生效。外层工具名称、真实来源校验和接受回执由应用接线。

## 最小验证

`tests/EmotionState.cpp` 检查旧存档原值、中性初始化、禁止直接赋值、无瞬时变化、
逐 tick 有界和限速、快速惊讶衰减、长期恢复中性、来源去重／活跃冷却、暂停与重启、
不强制改变身体／回答、私有字段过滤、坏存档原子拒绝、有界账本及混合情感粗分段。

2026-10-30 的 0.9 候选验证已有以下实际结果，并非仅源码审阅：

- 统一单元运行通过 307／307 场景、210069 条断言；其中 `EmotionState` 的 13／13
  场景、62755 条断言全部通过。入口日志为
  `artifacts/optimization-3h/20261030-113742/unit-090-fifth.log`，逐场景报告为当次构建的
  `test_reports/7ebad806.json`；这些计数不代表后续修改已经再次通过。
- `tests/EmotionReplies.ps1` 的隔离进程验收完成，19 项检查包含从真实旧 0.8.1 二进制
  写出的 RoleState v3 迁移到 v4、一次 actor 加一次 reviewer 处理最终 feeling、已接受
  回执、当前值渐进变化、不可用来源拒绝、同来源去重、显式暂停和新进程精确保留情感。
  日志为 `artifacts/optimization-3h/20261030-113742/emotion-process-fixed.log`，完整判定在
  同目录 `emotion-process/emotion-replies-43c59b73eaf243039e55d652b424f582/acceptance.json`。

  核对：各有三次请求，均未含 `emotion_drive`、`desire_drive`、`last_stimulus_seconds`

这些证据尚未覆盖真实模型提案质量、QQ 共享来源的端到端撤权／改号组合、持久化提交

阈值附近的候选刷新频率仍需后续观察；单元和合成进程通过不等于已经证明“像人”、
拥有感受、完成三小时最终候选长测，或已经安全部署到正式数据。
