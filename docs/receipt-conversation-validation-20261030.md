# 回执范围与自然接话专项

本项属于 2026-10-30 三小时改进任务。只读取了应用源码、八小时公开汇总，以及经授权的 `persona-validation-20261030-authorized/report.html`。没有读取正式聊天、记忆或工作区，没有更改角色人设、阶段与生产配置，没有发起真实模型调用。

## 具体问题与证据

公开补充报告指出：草稿正文已从蓝杯改为灰杯，更正记录仍保留蓝杯，但回复概括为“草稿里已不含蓝杯”。这是可明确核对的范围不一致。`src/WorkspaceTools.inc` 的局部编辑只替换唯一匹配片段，回执包含 `written`、`replacements` 和内容摘要，不承诺删除其他段落或历史记录。既有 `readingConduct()` 已区分节选、导言和正文，但没有明确区分当前正文与整份文件/更正历史。

作息报告还记录了回复中部分实现说明，不过输入本身提到程序支持方式，现有样本不足以认定这是规则导致的故障。因此这里只提出成对验证：相同 `rhythm.configure` 回执下，一题是普通安排休息，另一题明确问程序当前步骤。应分别保留自然接话和必要技术解释，不能把“更自然”变成隐瞒实际状态。

## 产品改动

- 新增 `include/Hibernation/ReceiptConversation.h`，提供两段共用稳定规则：按对方当前关心的结果组织回复，区分安排接受与实际睡眠；区分正文、全文件与历史范围，保留相关失败和不确定。
- `src/Review.cpp` 在角色和审核中使用同一段规则，不增加第三个审核者、不加入示范台词或固定确认模板。
- 直接对话策略版本由 2 升至 3，避免旧短反应缓存被当作符合新表达策略的候选。
- 不修改工具执行、文件权限、来源验证、存档与输出文本。不做关键词删除、标点改写或生成后的文本过滤。

规则允许直接回答当前正文，而不要求每轮主动讲更正记录；对方核对全文件时才说明相应范围。作息的“接受安排”仍不能写成“已经睡过”。明确询问实现、参数或失败原因时，相关技术细节仍允许且应如实提供。

## 本地验证与合成场景

运行：

```powershell
node tests/ReceiptConversationChecks.mjs --output=D:/Aliyat/HibernationAgent/artifacts/receipt-conversation-check
```

可选 `--baseline-source=<初始快照的src/Review.cpp>`，生成绑定旧、新规则指纹的对照请求包。检查脚本不连接网络、不读取生产配置或凭据，也不会调用模型。

`tests/ReceiptConversationScenarios.json` 包含八个现场：当前正文、全文件核对、只读正文片段、普通作息安排、明确问作息机制、读取被拒与不存在的区别、排队与完成的区别、换话题时不强带背景小物。17 个合成事实按“有支持 / 相矛盾 / 未知”核对，避免把缺失的存在性证据当作文件不存在。候选范例与评价标准只供评估，不放入角色或审核请求。

输出包括：

- `draft-scope.episode.json`：五轮真实工具场景，适配现有 PersonalityLab。实际写入后读取、局部改正文并保留更正，再分别问正文和全文件，最后换早餐话题。
- `routine-relevance.episode.json`：三轮场景，对照非技术口吻的安排与明确技术追问，最后换话题。
- `model-packets.json`：同一现场的旧、新共用规则请求。只有指定初始源码时才包含真实旧规则分支；没有指定时不伪造旧版本。
- `rubric.json`：与请求分离的事实、范围和相关性评价标准。
- `acceptance.json`：源码和场景指纹、检查结果及零模型调用声明。

本地检查核对事实夹具、相同证据的对照、请求隔离、共用挂载和版本，不声称理解了模型自然语言，也不以关键词计分判断人格。自然度和实际工具可靠性需要主代理统一额度下的旧/新真实模型对照。

## 真实对照的限制和判读

每个版本从独立的合成档案开始，使用相同角色范围、模型、审核设置和输入顺序；不得把新版承接旧版的记忆当作对照。正文更正场景需查真实文件及工具回执，不能只听角色说已完成；若工具失败或缺少读取，按失败保留，不补成预期结果。

分别记：当前问题有没有回答、操作事实是否可靠、断言范围是否超过实际读取、技术说明是否与提问有关、是否强带无关旧事/小物。技术词出现本身不等于失败，简短本身也不等于自然。若旧、新均通过或均失败，应如实记录；两个短场景不能支持统计性改善结论，也不能代替长期角色表现验证。

首个本地检查曾把事实总数误写成 18，实际为 17，随后修正断言。该失败属于测试清点错误，没有改动夹具事实或模型输出来取得通过。实际模型结果与集成编译由主代理另行记录。

## 程序边界与既有覆盖

已核对的现有覆盖包括：`Continuity.ps1` 原样保留有效拒绝、区分批准沉默与调用失败；`ProtocolIntegration.ps1` 覆盖拒绝、沉默、审核故障、工具失败去重与最终对白；`FailedAttempts.ps1` 覆盖失败经历的来源、版本、未写入、权限撤销与重启。它们不能独自证明真实模型不会无关自责或机械复述。

新增 `tests/ReceiptConversationProcess.ps1` 补充实际文件与发布边界：字面创建合成角色和阶段，只连接本机 TestProvider。写入蓝杯、完整读取、按真实内容 SHA 局部改灰杯后，检查原更正记录的蓝杯仍存在；随后检查简短失败对白原样发布而内部失败回执和恢复 guidance 仍可追溯；明确技术问句中的错误码仍可原样出现；真实接球语境的“接住”不会遭关键词删除。它不重新测试整套拒绝行为，也不将预置的批准当作模型审核质量证据。


候选默认要求策略版本 3，并核对角色和审核确实收到相同的新规则。旧版可显式传 `-ExpectedPolicyVersion 2`，仅验证共有程序边界，不能冒充新版验证。现有旧版 0.8.0 上 18 项通过，路径为 `artifacts/receipt-conversation-process/receipt-conversation-8acd72ba23bb453f9d9a920befad0a91`。首次进程夹具漏掉必要的 Mock 连接，启动以 `mock_required` 拒绝；修正测试配置后重新在新目录运行，旧失败目录保留。
