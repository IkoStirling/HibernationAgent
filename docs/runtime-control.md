# 运行、用量与跨机恢复管理

管理页新增三个折叠区域，不向用户展示角色记忆、原始对话或思维链。

- **此刻 → 运行状态与活动**：显示后台实际状态、等待原因、活动队列和语音状态。手动刷新不会覆盖尚未保存的配置。诊断下载仅包含程序状态、预算和模型用量计数，不包含记忆、提示词、密钥、连接地址或档案路径。
- **模型连接 → 应用调用额度**：后台独立日预算可以设置每天调用次数和输入 token 上限。关闭此限制仍保留原有每小时总额度。每日按北京时间重置；重启不会补充额度。输入限额根据已经报告的用量阻止下一次请求，单次请求可能超出上限，未报告用量的调用仍计入次数。
- **模型连接 → 模型输入与缓存用量**：按连接与用途查看累计输入、输出、缓存命中情况。未报告的指标显示“未报告”，不伪装为零。输入缓存与输出独立，统计覆盖功能启用以来的区间，不是每日账单。页面不使用当前模型价格回算历史混合模型费用，费用以供应商账单为准。
- **工作区与存档 → 跨机密钥备份与恢复**：先暂停并离线，再导出密码保护的密钥包。它不包含记忆正文或 API key，必须与完整存档备份一同保管。密码长度为 12–1024 UTF-8 字节。页面不会把密码、密钥包写入浏览器存储；提交后、失败后、离开此页时清空密码。

跨机恢复时选择已导出的 JSON 密钥包，填写包含 `manifest.json` 和 `data/` 的完整备份目录，验证通过后重新输入密码，指定**尚不存在的新数据目录**。恢复复制加密数据并重新保护密钥，不覆盖源档案、源备份，也不自动切换当前档案。完整备份内的角色和程序配置仍单独保留。先自行核对结果再决定是否切换；遗失密码无法找回。

前端通过 `/api/vault-portability/export`、`verify`、`restore` 提交操作，并随管理页刷新轮询 `status`。错误采用公共错误码展示；包内容、密钥与记录正文不会回显。只有正在跟踪的完成操作会处理结果，页面重新打开不会下载上一次已经完成的包。

验证：`node tests/RuntimeControlForms.mjs`。测试启动独立静态管理页和合成服务，覆盖预算保存及编辑保护、未知缓存指标、状态刷新、诊断字段白名单、密码清理、导出下载、验证后恢复、解锁失败与窄窗口布局；不调用真实模型，不读取生产档案。
