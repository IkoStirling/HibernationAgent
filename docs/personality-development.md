# 人格连续性：隔离培养与私下延续

核心人格和发展阶段仍是人工维护的定义。当前状态、记忆及自己逐渐形成的关注分别保存；一次对话不会把它们混成一份不断改写的系统提示。

`turn-v1` 的最终 `reply` / `silence` 可选 `carry_forward`，最多两条。其字段与 `self.notice` 一致：`id`、`expected_revision`、`kind`、`topic`、`note`、`stance`、`source_ids`。它表示角色愿意带到以后的具体关注、偏好或未完打算，不收集内部思维链，也不要求每轮总结。没有值得留下的内容就省略、传 null 或空数组。普通工具调用阶段不接受非空私记。

标准函数 `ha_turn_reply` / `ha_turn_silence` 也支持此可选字段。对白和私记一起通过语义审核后，应用逐条执行相同的 `self.notice` 权限、版本、来源、种类、连续数值与数量检查。带私记的沉默不能绕过审核；Skill 工具范围仍然适用。审核拒绝的候选不执行私记。操作槽持久记录，任务重试不会重复强化。私记失败的错误回执留在加密 trace 中，已通过的对白仍可显示；下一轮 self 中只有实际成功保存的条目，不能把提案视为保存成功。

这些内容和普通个人关注一样加密存档，聊天窗口只显示对白。它们不修改固定人设、阶段、正式小说设定，也不会自动宣告一个更大意图已经完成。原始交谈继续独立保留。

`self.observe` 可按 `query` 检索自己的关注，`status` 为 `active`、`closed` 或 `all`，`limit` 为 1–24；默认查询活跃关注。关闭的条目会带上当时做完或放下的缘由，检索不重新激活它。原始证据和结束证据都必须仍可访问，隐藏来源不会借此泄露。普通对话自动装配仍最多八条，避免把所有旧打算都压在每次回复里。

## 偏好形成与不同感受

一次表态的目标强度不再固定为正负 0.6。应用沿来源追溯独立经历：同一局灯谜的多个版本、同一小物、同一篇草稿的改写或同一阅读地址分别归为一件事；连续十五分钟内的交谈按一次相处归组，以该次最先入组的时间为基准。摘要和助手重述追溯已有来源，不另外发明经历。重复纯查询不增加独立依据，尚未实施的安排不产生偏好置信；观察已有棋盘只留下该局的弱印象，真正按下才提高这项经历的权重，即使整局仍未解开。

这是用于模拟的程序规则，不是心理测量。交谈权重为 0.5，具体创作、物件或游戏经历为 1；少量真实故事/任务来源为 0.75。目标为 `min(0.6, 0.12 × 总权重) × 正反加权平均`，仍按原来每秒最多 0.0005 的速度接近它。单次交谈最多趋向 0.06；运行时间、反复查看或重新组合旧来源不会让它继续变强。正反经历共同影响倾向，模型不能直接设置权重或数值。

同一旧事可以重新理解、改主意，其新看法会留下版本，独立经历数不增加。最近三次意义变化通过 `recent_changes` 提供，`basis` 表示经历依据，`stance` 是最近的感受；它们不规定对白必须含糊或解释数值。原始记录继续保留，活跃视图最多十二段经历、128 个独立依据，每条最多 128 次新增来源更新及 256 次意义/来源改动。

旧存档不会在读取、重启或普通 tick 中重新计算已有倾向。下次真正提出新看法/来源时才生成 v2 记录，保持当时数值再渐变，旧版本不覆盖。隐藏来源也不能通过变化历史或依据统计泄露。

不相关的普通对话只带上简短关注索引，详细旧事通过 `self.observe` 主动找回；相关话题、未完意图和私下活动仍能得到完整内容。这让持续关注保持可用，避免每句话都被同一段旧事占据。

## 谁说的话，谁的经历

装配记录外层的 `authorship` 由程序按原始记录种类生成：`counterpart` 是对方的话，`character` 是角色已经实际发布的话，`derived_record` 是摘要等派生记忆。报告者不等于句中感受的主体：用户可以转述朋友，也可以引用角色。角色和审核均须区分它们；角色此刻的新感受仍可自由表达，不需要发明过去来证明自己。

长原文被摘要替代时，外层仍保留原始说话者并标记 `derived`；记忆读取工具也提供记录归属。摘要连接收到原始记录种类及来源，要求保留转述、否定、纠正关系和主体，不把原文第一人称自动变成角色的经历。原始记录不添加或改写这些派生标签。

审核压缩上下文优先保留当前输入、候选引用的证据及较近记录，展示时恢复原有顺序，避免把纠正放到错误说法之前。已发布的旧对白仍可能记错，不能仅凭“是角色说过的”就把它重新确认为独立事实或偏好依据。这些标记帮助模型理解来源，不代表程序能够保证每次语义归属都正确。

## 生活背景与主动注意

普通用户交谈的能力环境提供 `ambient_index`：桌面小物数量与正在执行的互动、创作区可用空间、九盏灯实际身份/版本/进度。长期不变的小物描述、棋盘布局和草稿末尾不再自动放进每轮闲聊。真实姿态、动画目录和活动队列仍提供，角色不会因此失去对当前身体或动作的认识。

角色随时可主动 `habitat.observe`、`atelier.list` / `atelier.read`、`pocket.observe` 或 `capabilities.list` 获取完整当前内容；权限和版本检查照常执行。前四种只读操作不额外消耗一次语义审核，写入、按灯等操作仍审核。私下考虑、自主规划和审核继续获得完整现场，不把简化的闲聊背景误当成资料已删除或插件没有能力。未知插件保持其现有发布合同。

这个投影减少背景对发言主题的牵引，不规定每次回复的语气、禁止旧事或强迫查询。角色仍能相关时想起同一件事，也能只接当下的话。

普通交谈的 `conversation_delivery.mode=direct_utterance` 是表达载体，不是新的人格设定：最终文字直接写可对对方说出的台词，玩笑不自动变成小说舞台。角色和审核共用这项规则；审核只修正载体、保留原意，不因旁白清空经历或撤销动作。用户明确请求故事、剧本、诗或虚构场面时仍可采用创作文体，也允许正常引用原话，不通过删引号或关键词替换加工已批准的文字。拖动短反应沿用同一直接交谈规则；表达规则版本进入缓存签名，旧缓存不自动混用。

## 打算与尝试

活动命令可选 `intention: {id, revision}`，接续一个已经实际保存、仍活跃且证据可见的 intention。入队时核对版本，整批不满足就不部分执行；真正开始和执行期间也重新核对。修改或放下打算后，旧步骤不继续执行。随手玩、走动和休息不必变成一个目标。刚产生的打算若要本轮立即绑定，先用 `self.notice` 取得版本；不能引用尚未保存的最终私记。

程序在私有进展中留下最近六项尝试，包括真正完成、被新输入打断，以及根本没开始的排队步骤。更早记录仍保留在加密档案。完成一个动作不会自动关闭更大的打算；需要角色依据实际结果自行选择继续、完成、改变主意或放下。已开始的有限写入在取消后真正落盘时，另记其实际 effect 结果，不伪装为撤销成功。

这些进展通过 `self.threads[*].attempts` 提供，属于私有派生视图。其记录编号不能单独作为新记忆或阶段变化的经历证据；`self.observe` 本身也不会制造新的外部经历。实际工具结果通过 `result_sources` 提供原始来源，仍经过权限和版本核对，可用来引用真实创作等结果。复用成功动作时剥离旧 intention 绑定，不能把旧目标偷偷重新执行。

私下考虑也可来自角色真正创造的小物、解开或主动放下的一局灯谜。每个来源只给一次机会，允许无更新；单次普通按键不触发总结。管理员试用插件不会借用成角色自己的创作经历。操作回执中“整局未完成”与“按键尚未执行”分别处理，实际进度元数据在压缩后仍保留。

## 在自己的活动中形成关注

自主规划的现有 JSON 可选 `carry_forward`，最多一条，结构与对话私记一致。角色可以在已有相处、真正创作或玩过以后，自己留下兴趣、偏好或还想做的事；省略、null、空数组都合法，不增加独立的模型调用。审核只审其来源、主体和连续性，不替角色写人格，也不要求每个动作聪明、有用或每批都有心得。

应用提供至多六条可访问的原始 `evidence`，包括近期真实动作回执、桌面经历及交谈，保留种类、报告者和修订。长交谈标明节选；图像这里只给元数据，不把它说成当前又看到了像素。模型不能用刚排的计划、自身私有进展或猜出的编号作来源。落盘前重查来源权限/版本，仍通过 `self.notice` 的完整参数、语义版本、数量、连续数值和重复保护，不改核心人格或阶段。

只在当前模式、当前交谈代次和有效时间内，且命令批实际通过入队检查后保存。输入打断、暂停、模型/配置变化、超过两分钟的规划或审核失败均不补写。私记失败不伪装为成功，也不撤销独立有效的动作；队列拒绝则不执行私记。当前命令只能绑定先前已保存的 intention，新建或改变的私记从下一次规划接续，不能假定尚未拿到的保存回执。

结果进入加密的生成记录和稳定操作槽；下次规划收到最近十分钟内的 `previous_carry_forward_results`（编号、成功/失败、真实版本），self 中只有真正保存成功的内容。普通聊天只展示对白，管理状态的 `personal_carry_feedback` 不含私记正文。计划格式/不可用、审核格式/服务不可用、审核语义拒绝分别记录，不把通信或解析失败说成角色的选择不合格。审核仍失败关闭，不因故障绕过它；后台审核最多等待配置值与20秒中较短者，用户新输入可取消。

自主命令增加 `puzzle_leave`，使用真实 game_id 和 expected_revision，seconds=0。角色可自己放下一局未解完的九盏灯，保留原棋盘和尝试，不假装赢了；不能由峰时缓存重复执行。当前有活跃局才提供 press/leave，没有活跃局才提供 start，避免一直提示无法新开的游戏。主动放下的实际回执仍能成为以后重新理解的依据。

自主规划也可选 `close_threads`（至多一条），参数与 `self.close` 一致：id、expected_revision、outcome、note、source_ids。completed 用于已有实际结果的具体意图；abandoned 表示改变主意，released 表示暂时放下。可同批结束一个旧关注并留下另一个不同id的新关注，同一id的关闭/新增冲突、关闭后还给它排动作的批次会被拒绝。关闭先执行，新关注随后执行；每项仍有独立的稳定操作槽、来源、版本、审核和成功/失败回执。旧经历和结束缘由保留，可用 self.observe 的 closed/all 查询。

一次真实按键、观看或读写可以完成“试一下、看一次变化、写一小段”这样的局部意图；这仍不证明更大目标已经实现。审核须对照目标含义与实际结果，未解开的棋盘不能说成赢了。程序要求原始实际操作/观察来源，私有进展记录或尚未实施的安排不能单独证明完成。

旧意图改变或结束时，应用仅停止其失效绑定的活动、移除相关未开始步骤，保留无关活动与其他有效意图的步骤。过期但未开始的步骤也记为未启动结果。已在执行的有限写入若随后实际完成，仍留下真实 effect 回执。每帧共享一次可见性判断、同一绑定只核对一次，避免同队列重复扫描记忆库；真正开始前仍重查。

## 持续的培养档案

`tools/PersonalityLab.ps1` 在项目 `artifacts` 中建立专用档案，冻结宿主及插件、复制公开角色定义。后续 episode 继续打开同一加密档案，保持真实经历、草稿与状态；停止期间不虚构新的经历。Mock 和真实连接不可混在同一档案。实验不读取或复制正式聊天，仅临时复制所选连接的 DPAPI 凭证，后台初始化后立即清理副本；后台仅保留进程内凭证，退出也执行清理。

实验输入为 `{ "version": 1, "title": "…", "turns": [{ "text": "…" }] }`；`settleSeconds` 可用有限时间观察已安排动作的真实结果。它用于有联系的相处与选择，不是能力考题矩阵。每段报告保留实际回复、私记、工具回执、审核、连续状态及构建指纹，便于区分说了什么、记住什么、真正做了什么。

Episode 可显式开启 `autonomy`，以 `opportunitySeconds` 给一次最多 45 秒的独立活动机会；`considerOwnWork` 在真实活动之后请求一次可无更新的私下考虑。素材由应用挑选尚未考虑过的实际阅读或创作，不把实验提示当成角色亲历，不强制日记、主动发言或新的偏好。

调用必须显式传 `-Live`，默认 Mock。真实连接统一经 `PersonalityBudget.mjs` 本地计量转发；`BudgetLedger` 在所有对照分支之间共用。实验的请求上限和 token 上限在调用前预留，并持久记账；角色、审核、修复、重试和失败都占请求。上游报告用量时按实际 input/output token 结算，缺失用量或崩溃保留保守预留，不能按零计费。账本只含时间、连接标识、数量和状态，不写密钥、正文、认证头或推理内容。

转发器只监听本机、使用随机路由能力、固定配置的上游及两种模型端点，不跟随跳转；运行窗口截止后拒绝新请求。独占锁防止并行进程各算一份额度。崩溃遗留的锁需先确认进程结束，再人工清理，不能自动抢锁或重置账本。Node.js 由 `HA_NODE_RUNTIME` 或参数提供，运行实验不会引入产品的 Node 依赖。

当前这轮窗口、限额、发现与真实消耗见 `ai-logic-worklog.md`；额度是上限，不是必须消耗的指标。模型接线只做必要摸底，主要观察经历如何形成持久的关注、取舍与后来的主动行为。

## 在同一生活中继续交谈

`-Serve -ServeUntilUtc <UTC截止>` 保持同一后台，允许角色真正完成自己的活动，开发者在另一候选构建中修改代码。`ServeUntilUtc` 不得晚于总 `DeadlineUtc`，计量转发采用较早截止；到时关闭后台和转发器，不继续付费活动。截止前也可主动停止。更新冻结运行包时，先停止并确认进程结束，再用 `-RefreshRuntime` 打开同一档案。

使用 `tools/PersonalityLabCommand.ps1 -LabRoot <档案目录> -Action say -Text <合成交谈>` 续接。其余动作仅为 `episode`（1–12轮）、`snapshot`、`consider`、`rebuild_dialogue`、`stop`；`episode` 配合 `-Episode <JSON路径>`。文件命令箱不执行脚本，拒绝未知动作、过期控制器和当前动作以外的字段。控制器清单只含进程身份、截止和报告路径，会核对实际进程及启动时间；应用管理会话令牌只在控制器内存，不写入命令箱、清单或参数。

维护更新时 `-Serve` 可使用零轮 episode（如 `resume-own-life.json`），继续同一档案而不制造新的用户交谈。显式 `rebuild_dialogue` 只调用已有的工作对白投影重建接口，在报告中记录实验干预；原始历史、已做事情、人设、阶段和连续状态保留。它用于定位旧话语对表达的牵引，不自动作用于正式档案，也不把一轮观察当成稳定人格改善。

命令观察超时不能当成未执行：应查看返回的结果路径和实际后台状态，不盲目重放。命令身份同时用于应用请求去重。`consider` 等待本次独处任务自己的运行令牌和结束状态，不能把“聊天空闲”误当成独处已完成。停止回执之后仍需确认控制器及后台退出、计量锁释放。

持续运行本身不是实验成果或长稳测试。应交替进行实际开发与有联系的相处，检查它自己选了什么、实际做了什么、后来如何看待；不以空等或重复调用填满开发时段。
