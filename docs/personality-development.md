# 人格连续性：隔离培养与私下延续

核心人格和发展阶段仍是人工维护的定义。当前状态、记忆及自己逐渐形成的关注分别保存；一次对话不会把它们混成一份不断改写的系统提示。

`turn-v1` 的最终 `reply` / `silence` 可选 `carry_forward`，最多两条。其字段与 `self.notice` 一致：`id`、`expected_revision`、`kind`、`topic`、`note`、`stance`、`source_ids`。它表示角色愿意带到以后的具体关注、偏好或未完打算，不收集内部思维链，也不要求每轮总结。没有值得留下的内容就省略、传 null 或空数组。普通工具调用阶段不接受非空私记。

标准函数 `ha_turn_reply` / `ha_turn_silence` 也支持此可选字段。对白和私记一起通过语义审核后，应用逐条执行相同的 `self.notice` 权限、版本、来源、种类、连续数值与数量检查。带私记的沉默不能绕过审核；Skill 工具范围仍然适用。审核拒绝的候选不执行私记。操作槽持久记录，任务重试不会重复强化。私记失败的错误回执留在加密 trace 中，已通过的对白仍可显示；下一轮 self 中只有实际成功保存的条目，不能把提案视为保存成功。

这些内容和普通个人关注一样加密存档，聊天窗口只显示对白。它们不修改固定人设、阶段、正式小说设定，也不会自动宣告一个更大意图已经完成。原始交谈继续独立保留。

`self.observe` 可按 `query` 检索自己的关注，`status` 为 `active`、`closed` 或 `all`，`limit` 为 1–24；默认查询活跃关注。关闭的条目会带上当时做完或放下的缘由，检索不重新激活它。原始证据和结束证据都必须仍可访问，隐藏来源不会借此泄露。普通对话自动装配仍最多八条，避免把所有旧打算都压在每次回复里。

## 打算与尝试

活动命令可选 `intention: {id, revision}`，接续一个已经实际保存、仍活跃且证据可见的 intention。入队时核对版本，整批不满足就不部分执行；真正开始和执行期间也重新核对。修改或放下打算后，旧步骤不继续执行。随手玩、走动和休息不必变成一个目标。刚产生的打算若要本轮立即绑定，先用 `self.notice` 取得版本；不能引用尚未保存的最终私记。

程序在私有进展中留下最近六项尝试，包括真正完成、被新输入打断，以及根本没开始的排队步骤。更早记录仍保留在加密档案。完成一个动作不会自动关闭更大的打算；需要角色依据实际结果自行选择继续、完成、改变主意或放下。已开始的有限写入在取消后真正落盘时，另记其实际 effect 结果，不伪装为撤销成功。

这些进展通过 `self.threads[*].attempts` 提供，属于私有派生视图。其记录编号不能单独作为新记忆或阶段变化的经历证据；`self.observe` 本身也不会制造新的外部经历。实际工具结果通过 `result_sources` 提供原始来源，仍经过权限和版本核对，可用来引用真实创作等结果。复用成功动作时剥离旧 intention 绑定，不能把旧目标偷偷重新执行。

## 持续的培养档案

`tools/PersonalityLab.ps1` 在项目 `artifacts` 中建立专用档案，冻结宿主及插件、复制公开角色定义。后续 episode 继续打开同一加密档案，保持真实经历、草稿与状态；停止期间不虚构新的经历。Mock 和真实连接不可混在同一档案。实验不读取或复制正式聊天，仅临时复制所选连接的 DPAPI 凭证，进程结束后清理副本。

实验输入为 `{ "version": 1, "title": "…", "turns": [{ "text": "…" }] }`；`settleSeconds` 可用有限时间观察已安排动作的真实结果。它用于有联系的相处与选择，不是能力考题矩阵。每段报告保留实际回复、私记、工具回执、审核、连续状态及构建指纹，便于区分说了什么、记住什么、真正做了什么。

Episode 可显式开启 `autonomy`，以 `opportunitySeconds` 给一次最多 45 秒的独立活动机会；`considerOwnWork` 在真实活动之后请求一次可无更新的私下考虑。素材由应用挑选尚未考虑过的实际阅读或创作，不把实验提示当成角色亲历，不强制日记、主动发言或新的偏好。

调用必须显式传 `-Live`，默认 Mock。真实连接统一经 `PersonalityBudget.mjs` 本地计量转发；`BudgetLedger` 在所有对照分支之间共用。实验的请求上限和 token 上限在调用前预留，并持久记账；角色、审核、修复、重试和失败都占请求。上游报告用量时按实际 input/output token 结算，缺失用量或崩溃保留保守预留，不能按零计费。账本只含时间、连接标识、数量和状态，不写密钥、正文、认证头或推理内容。

转发器只监听本机、使用随机路由能力、固定配置的上游及两种模型端点，不跟随跳转；运行窗口截止后拒绝新请求。独占锁防止并行进程各算一份额度。崩溃遗留的锁需先确认进程结束，再人工清理，不能自动抢锁或重置账本。Node.js 由 `HA_NODE_RUNTIME` 或参数提供，运行实验不会引入产品的 Node 依赖。

当前这轮窗口、限额、发现与真实消耗见 `ai-logic-worklog.md`；额度是上限，不是必须消耗的指标。模型接线只做必要摸底，主要观察经历如何形成持久的关注、取舍与后来的主动行为。
