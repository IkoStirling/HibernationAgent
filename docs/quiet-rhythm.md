# 安静节律：休息也要有实际过程

可选插件“安静节律”依赖桌面小角色。模型获得 rhythm.observe/rest/wake：可以了解
大致精力与系统本地时段，选择15至1800秒的短暂休息，或结束休息。它不锁定电脑、
不改变系统声音、不要求用户陪同，也不会每次结束就主动发话。

休息先是 queued 意图。当前交谈、文字/语音呈现或其他动作结束后，才请求小角色
进入休息姿态；收到真实姿态确认再进入 active，保存有来源的开始经历。accepted
不能证明已经休息完成。实际经过的运行时间到达时长后结束，另存完成经历。
交谈、输入、拖动、隐藏角色、模型选择醒来或停用插件都能中断；正在休息时，
桌面小物的自主接近不能把角色拉走。姿态请求超时和过期意图会取消。

实际开始/结束刺激既有连续状态机，精力仍缓慢变化，活动有原有驻留时间，不直接
覆盖数值。结束时只释放本插件仍拥有的活动，不覆盖模型后来选择的其他活动。
暂停冻结计时。重启结束上一次间隔，记录上次真正运行的秒数，不补算离线休息。
插件装卸使用稳定的间隔身份去重，不重新播放动作或产生重复经历。

自动模式默认在空闲至少5分钟后，以30%的概率考虑一次；通常只在夜间或精力较低、
当前没有其他活动时休息，每次考虑至少间隔一分钟，完成后至少十分钟再考虑。
这些偏好可在管理页配置。依据系统本地时钟，不由天气位置猜测时区；不是医学或
用户作息评估。自动模式不调用模型，用户仍可选择关闭。

正文和状态进入加密账本；agent.world.rhythm.* 只存元数据索引，和桌面小物共用
已有事件总线及持久待办恢复机制。开始、完成和持续至少一秒的真实中断可供后续
对话引用；取消意图不冒称经历，不自动改变人格阶段或关系。

验证：纯状态机检查姿态确认、暂停、过期/新对话和重启边界。独立不可见桌面的
22项进程检查覆盖15秒真实休息、缓慢精力变化、与食物协作、快速拖动中断、对话后
再开始、计划记忆拒绝、重启不虚构离线经历、装卸恢复和重复结束去重。
