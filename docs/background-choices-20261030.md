# 闲时情绪与稍后计划

0.9.1 将已有独立入口接到日常活动规划，不重做记忆架构，也不增加每批模型调用。
原先 `commands`、`appraisal`、`carry_forward` 和 `circadian_routine` 均兼容。

活动模型返回中新增两个可省略或 null 的字段：

- `feeling`：与最终会话和 `self.feel` 使用同一 `source_id`、`stimulus` 结构。
  只引用本批 `evidence` 中可访问的真实经历，经原审核和宿主校验后更新刺激，
  继续沿用五秒活跃冷却、来源去重、限速和衰减，不直接设置当前情绪。
- `schedule`：至多一个 `schedule.create` 提案，包含 `id/topic/memory/when/source_ids`。
  同一批审核后由现有定时任务实现执行。无来源、来源撤权、容量满、ID 已存在或暂停
  会返回失败回执，不将失败记作已安排。不接受任意工具或调度器内部参数。

`schedule_configuration` 提供权限、单批上限和最多六项可访问的已有计划。
这些计划的全部来源也绑定到规划上下文权限检查；其原始来源被限制时，不能继续
通过计划内容保留旧上下文。已有计划供角色避免重复创建，不要求它每批规划、表态
或主动发言。自然语言仍由角色自由选择，未增加台词模板。

两个字段均走现有 `applyPrivateOperation`、真实来源验证和持久化回执；结果进入
下一轮 `previous_carry_forward_results`。审核通过不是执行成功，创建计划不是
完成经历。已存在计划的修改、暂停、取消仍可通过完整会话的原调度工具进行。

默认 `solitude.timer` 曾可能在重试耗尽后永久停在 Failed，而启动只检查 ID 存在。
新增低频维护只在在线、未暂停、未睡眠且日预算可用时恢复这一保留周期任务，
安排一个未来时点，至少等待一分钟并沿用配置周期；不补跑缺失次数、不清零预算、
不恢复已暂停的任务、不修改角色自己取消的计划。恢复写入 `cognition.schedule.recovered`。

本次预算重置是用户授权的一次性维护，限定原记录与唯一回执，不提供新的常驻
重置 API、模型工具或自动重置策略；历史用量、原始版本和每日限额保留。

验证入口：`EmotionState` 的活动协议检查、`AutonomousCarry.ps1` 的同批感受／计划、
去重和下一轮可见回执，以及 `ActivityRecovery.ps1 -Case failed-timer` 的真实失败队列恢复。
