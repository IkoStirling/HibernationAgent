# 三小时优化与实验计划

授权窗口：北京时间 2026-10-30 11:37:42 至约 14:37:42。
开始时正式程序已为先前通过检查的 0.8.0；上轮补充只增加 PersonaOnly 隔离验证入口，
不含尚未部署的产品功能。本轮形成新的经验证候选后更新正式程序。

四路并行：

1. 主任务负责基线、统一构建、长时间进程观察、受限真实模型实验、部署与证据归档。
2. 缓存与调用效率：定位审核前缀及重复无效调用，保护来源权限和实际用量的真实性。
3. 活动与作息：预算暂停和恢复、活动队列补充、睡眠及刚醒阶段的连续衔接。
4. 表达与可靠性：针对技术复述、强行续话及动作回执做具体改进和合成对照。

源码和正式数据分别保留在 D 盘与原 E 盘位置；实验使用独立目录，禁止将测试数据
覆盖正式档案。真实模型只接收已授权的现有人设、程序说明、合成对话和虚拟状态。
不读取或外发正式聊天、真实屏幕、正式工作区或小说参考内容。密钥不进入日志。

API 计数继承先前 131 次记录，总上限仍为 1000；本轮另设较小实验额度，按问题
逐步使用而不为耗完额度制造调用。真实供应商缓存和本地前缀分析分别记录，不混为一谈。

先保存初始源码指纹、正式程序指纹和配置/档案位置元数据，再开始修改；保持正常
分支和暂存区。长测使用固定程序副本并记录实际经过时间，不把不同构建的时长相加。
候选先通过单元和独立进程验证，程序更新时正常保存退出，保留用户配置、密钥和档案，
记录程序回退副本。仅工具或文档改动不为了“应用”而无意义重启正式后台。

结果以实际收齐的检查、模型回执和长测样本为准。短样本表达改进不宣称长期人格改善，
连续性指标不作为意识证据。未通过或受外部条件限制的项目保留原始结果。

## 12:20 追加的优先事项

用户要求将感情与欲望模块、多条回复纳入本轮完成，部分研究验证可顺延。优先级调整为：

- 感情／欲望：沿已有连续状态管理，刺激必须有来源、受限且可追溯；允许喜怒哀乐、
  希望、拒绝与克制的挖苦，不强制讨好、骂人或关系升级。情绪强度逐步响应及衰减，
  不允许模型直接覆写数值，不把传统名称当作科学定律或体验证明。
- 多条回复：一次模型返回可以选择一条长回复或多条独立消息；QQ 提供多条短回复偏好。
  所有条目先整体校验和审核，再逐条存档与交付；保持共同来源和顺序，旧单条协议兼容。
  部分发送失败、重启、离线及权限变化须保留明确回执，不能补发已确认发送的旧消息。
- 暂缓新增风格对照和扩大长测组，保留已有实验结果；新增协议、持久化、顺序交付与
  权限等关键检查仍在正式更新前完成，后续长时间表现验证单列待办。
