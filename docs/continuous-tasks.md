# 持续目标与对话分流

角色在同一次对话调用中选择直接交谈、当轮工具操作或持续目标。程序不按关键词强制建任务，也不增加一个独立分类模型。普通问候、分享、知识问答和“先别做”的设想应直接交谈；一步操作继续使用原工具；接受需要后续推进的明确目标时才调用 `task.start`。模型可以拒绝、询问范围或暂放。

## 执行与状态

接受目标后先返回自然对白，后台沿已有 WorkerHost / DurableQueue 分段执行。每段读取当前目标、简短进度、原始指示、近期真实操作依据和现场状态，调用现有受控工具，以 `task.checkpoint` 保存进度及下一步。检查点不是模型思维链。普通进度允许沉默，成果和需要用户回答的问题再交付。

状态包含待继续、执行中、等用户补充、暂放、受阻、完成和放弃。插入闲聊不清空目标。Dashboard“此刻 → 持续目标”可查看简短进度并暂放、继续、取消；也可在对话中控制或修改目标。所有控制使用版本号，旧页面不能覆盖已更新进度。

等待用户、暂放、受阻和结束状态不自动调用模型。一般新输入优先于后台，沿用原有互斥和让出机制。已有动画队列、朗读或其他后台工作仍受原有调度条件约束，任务不是实时抢占式执行。

## 真实结果、恢复和权限

- `task.start` 成功只表示目标已保存，不能当作完成。完成检查点需要实际操作或观察来源；用户要求、任务回执、自我总结、私记和单纯状态提案不作为完成证据。语义审核还需比较真实回执与完成条件。
- 使用加密 RecordStore 保存目标、检查点、工具证据和来源链。正式原始档案不删改。对话上下文仅提供有界摘要及来源，必要时通过原有检索/回看工具读取详情。
- 每个任务绑定接受时的工具集合、工作区和用户来源。后续启用新工具不自动扩大旧任务权限；隐藏/撤回来源、工作区改变和 QQ 权限变化会阻止继续执行。Skill 不能创建或修改持续目标，也不能借任务扩大授权。
- 同一任务步骤使用稳定操作标识和原有执行回执，恢复时不会仅因重试就重新执行已确认的副作用。已保存检查点而最终对白被中断时，重启可直接结算检查点，无需重新生成对白。
- 未知结果不等于成功；永久错误/无检查点阻止自动继续，有限临时错误使用退避。连续三段没有新增实际工具证据则停止自动尝试。读取也算实际证据，故此防护不能替代语义审核判断“工作是否有用”。

## 配置与边界

```json
"continuousTasks": {"enabled": true, "maxActive": 3, "maxSteps": 24}
```

`maxActive` 范围 1–8，`maxSteps` 范围 1–100。待补充、暂放、受阻目标仍占活动名额，取消/结束后释放。每项目标默认有效期 24 小时；达到步数或期限后停止。继续按钮不增加预算；应用每小时额度、审核、超时和每轮工具次数继续生效。每轮至少需要两个工具阶段才能推进并保存检查点。不支持任务自己递归创建任务、定时任务或激活新 Skill。

QQ 仅向具有桌面控制权限、允许共享记忆的号主私聊提供任务能力；群聊、其他用户和严格隔离模式不获得此权限。原始 QQ 消息保留在独立数据库，通过带来源的引用授权桌面后台执行。当前后台任务成果显示在桌面；不主动发送 QQ，可在原会话查询。此能力不是无限连续运行，也不承诺任意模型都能可靠规划。

## 对话里的持续任务

桌面对话顶部的“持续任务”显示未结束目标数量。打开后进入聊天的任务区，可查看实际状态、已启动的工作段，以及近期结束的目标。暂放、继续和取消沿用后台任务版本检查。

聊天任务接口只提供任务名称、程序状态和控制所需的版本号，不发送检查点、下一步提示或模型执行记录。展开任务可查看实际写入或编辑成功的文本草稿。预览读取工作区中的当前文件，需通过原来的工作区检查和任务来源校验。

## 验证

`Hibernation_UnitTests` 检查结构、完成证据、权限边界和原生工具 Schema。`Hibernation_ContinuousTasks_json` / `_native` 使用独立应用进程、合成 HTTP 提供方、真实工作区文件和加密库，检查接受/执行分离、分段依赖、插入对话、真正重启、检查点中断恢复、伪完成拒绝、等待/恢复、无进展停止、旧版本冲突、来源撤回、工作区改变和工具阶段不足。

`Hibernation_ContinuousTasksForms` 以真实浏览器操作 Dashboard 的继续、暂放和取消，并保留截图。NapCat 集成检查还验证号主私聊委派到桌面后台，以及群聊/其他用户不获得此权限。测试数据仅使用隔离合成档案。
