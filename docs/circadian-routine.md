# 自主作息与执行核验

这是应用层的虚拟作息实验，复用节律插件、小组件、后台规划、审核和加密存档。
它验证可观察的控制与反馈，不据此判断主观体验。

## 自主设置与管理

启用 `rhythm` 插件及其“允许它自主配置作息长睡”选项后，角色可以设置自己的时段。
首次使用没有预置作息，不会因为插件启用就强制长睡。角色可以在交谈／独处中调用
`rhythm.observe`、`rhythm.configure`，也可以在现有闲时规划中提交可选
`circadian_routine`。沿用原来的角色与审核连接，不增加专门的作息模型。

日常使用无需手写下面的 JSON：可以向它说明你希望允许它安排自己的休息，由它根据
已知经历提出选择。管理页保留自主作息总开关与强制唤醒；强制唤醒结束这一时段的
自动长睡，普通交谈能否唤醒则按它已保存的倾向判定。状态页显示休息阶段和实际累计
时间，私有作息提案、判断和记忆正文不会因此公开。

角色配置例子（当地时间 23:00 至次日 07:00）：

```json
{
  "expected_revision": 0,
  "preferences": {
    "enabled": true,
    "start_minute": 1380,
    "end_minute": 420,
    "drag_wake_probability": 0.2,
    "message_wake_probability": 0.65,
    "inertia_seconds": 600
  }
}
```

`expected_revision` 必须来自当前 `preferences_revision`。时段可跨午夜，长度为
1 至 12 小时；唤醒概率为 0 至 1，惯性衰减时间为 30 至 3600 秒。模型不能直接
设置当前睡眠时间、惯性值、情绪或执行结果。闲时提案是上述对象放入
`circadian_routine`，可以省略或为 `null`；不要求每批修改。

角色可将 `preferences.enabled` 改成 `false`。管理员也可关闭插件设置中的作息开关，
或使用管理页“现在唤醒”。管理端 `POST /api/rhythm/wake` 接收空对象，暂停时仍可用。
普通页面保持对白显示，不展示私人笔记、判断或作息提案内容。

## 实际状态与中断

- 时段决定可休息的机会；已有活动、交谈和朗读结束后，才尝试进入休息。
- 配置接受、姿态请求、实际开始、实际结束分别记录。配置回执的 `accepted` 不代表
  已经睡过；配置事件与加密插件检查点共同提交。
- 只有收到匹配的 `widget.rest_started` 回执才计时。暂停不计时，关机时间不补算。
- 机器挂起或系统时间变化后重新核对当地作息窗口；已经离开的旧窗口结束，保留
  实际累计时间和连续惯性，不把挂起期间补算成已休息。正常跨午夜仍属于同一窗口。
- 拖动仍能提起、移动并落地。未唤醒时，落地后回到睡姿；动画结束时间与休息租期分开。
- 普通消息按角色倾向判定是否唤醒，同一段短时间内不反复抽取概率。未唤醒的消息
  仍进入原始加密档案及对应渠道记录，当轮安静结束，不调用模型，不延后补播旧反应。
  接收时的事实元数据明确标记“休息中收到，当时未提交给模型”，不会伪称当时已经看过。
- 普通打扰成功唤醒后，至少保留十分钟清醒缓冲；仍在原时段且闲下来时可再睡。
  主动唤醒和管理员强制唤醒会结束当前时段的自动长睡。
  随后明确修改起止时段或重新启用作息可产生新的休息机会；仅调唤醒概率不会重新
  激活已结束的同一时段。
- 休息期间持续目标和到期提醒暂缓，保留原目标、步数和提醒机会；不计模型调用，不因
  缺少新检查点误记失败。醒来后继续检查权限、期限和预算，过期机会仍如实标记。
- 睡眠准备度在休息中逐渐变化，醒后逐渐衰减。程序只提供实际状态和打断原因，允许
  角色迷糊、安静或轻微不快，不强制起床气台词，不将技术失败解释成用户的过错。
- 拖动反应缓存区分休息、刚醒和稳定清醒三个粗粒度阶段，跨阶段的旧候选不再使用。
  连续惯性值仍提供给生成连接，但不把精确数值或时钟放进缓存键，避免每帧失效。
- 睡眠中重启会明确结束旧租期，保留已发生时间；仍在原时段时可重新进入休息。
  主动结束或已醒来的同一时段不会立即重复入睡。旧操作与旧回执不重放。

现有 `rhythm.rest` 短休仍保持原规则，可以直接被交谈和拖动打断。
动作素材沿用已有躺下、睡姿、起身、拖拽和落地；没有声称新增专用“起床气”序列帧。
完整接线及素材覆盖见 [角色动作总表](character-action-catalog.md) 的 REST-01～07。

## 可追溯性

连续认知开启时，注意变化、判断更新、打算恢复、动作入队／开始／结果／延后回执，
以及睡眠提案和实际回执进入 `ha.cognitive-trace`，由现有存档加密层保存。
日志不要求或保存模型内部思维链。实际工具回执仍保留原有来源。

管理端 `/api/mind/trace` 只返回白名单元数据，近期索引保留 500 条；加密原记录不因此删除。
分页限制最多 100 条。程序不会把自己的审计记录当成新的外部经历再次喂给角色。
角色、判断内容、动作目的、记忆与工作区文本不出现在该管理接口或诊断导出中。

审计会批量封存，正常周期为 500 毫秒、队列上限 128 条；异常退出可能留下尚未封存的
尾部。独立的加密会话标记在下次启动时区分“正常封存”和“未正常封存”，管理页明确
显示不确定性，不补造缺失的动作或声称轨迹完整。原始交谈与实际操作本身的提交记录
独立保留；正常退出先写入待保存轨迹再封存会话。

## 日常核对

从托盘重新打开管理页，可查看当前休息阶段、连续认知状态和实际调用用量；更新后台后
旧网页的本机会话可能失效，重新从托盘打开会带上新会话。读取这些状态不调用模型。

“后台等待每日额度”与“接口余额不足”是不同状态。后台日预算默认限制调用次数和
已报告的输入量，输入量也包含供应商命中缓存的部分；到限后不会再主动调用模型补充
作息或反应提案，前台仍按自己的每小时额度工作。已有作息的本地计时、睡姿确认及
唤醒判定继续运行。需要调整预算时在管理页明确设置，不靠重启清零旧计数。

认知轨迹由按钮明确刷新，只显示动作种类、状态、版本、来源编号及简短原因。用相同
关联编号可以对照既有事件总线；不会在普通管理页展开记忆、私记、工作区内容或内部
思维链。近期列表仅保留 500 条元数据，超过列表上限不等于原始加密档案被删除。

- 配置“已接受”表示提案通过校验，不表示角色此刻已经睡着。须等 `sleep_started`
  和小组件实际姿态确认，程序才累计这段休息。
- 活动“已排队”“已开始”和“实际结果”分别记录；中断后才到达的结果另行关联，
  不将最初的计划或口头承诺写成已经发生。
- 休息中未唤醒的输入仍保留，记录说明当时没有提交给模型；醒来不会补播那些旧轮次。
- 管理员可以关闭自主作息或强制唤醒。新起止时段仍需正常验证，不靠直接改写心情或
  人格实现；睡后惯性是连续状态，角色是否抱怨没有固定台词。
- 正常封存与异常退出是两种记录。异常标记意味着尾部可能有缺口，不能把缺口解释为
  它从未有过活动，也不会凭空补写一段经历。

## 验证入口

- `Hibernation_UnitTests --suite CircadianRhythm`：窗口、版本、概率、暂停、重启、连续状态、QQ 门控。
- `tests/CircadianNative.ps1`：独立桌面进程的姿态、拖动、消息保存、管理员唤醒和存档恢复。
- `tests/CognitiveAuditCrash.ps1`：只强制结束保留句柄的隔离子进程，验证原始记录、异常封存标记与随后正常退出的区别。
- `tests/CircadianReactions.ps1`：休息阻断补充反应，醒后候选分段失效，连续惯性不会每帧重建缓存。
- `tests/CircadianQQ.ps1`：真实本地回调及插件链路，休息中零模型调用、零发信，唤醒不重放旧消息，新消息携带当前身体状态。QQ 与模型均为回环服务，不联系真实账号。
- `tests/CircadianPlanning.ps1`：本地角色／审核替身的闲时提案、拒绝、旧版本和禁用检查。
- `tests/CircadianTasks.ps1`：实际等待任务到期，检查睡眠暂缓、零调用和唤醒后恢复接续。
- `tests/ContinuityMind.ps1`：判断修正、来源权限变化、打算恢复、防重放及加密执行痕迹。
- `tools/ContinuitySoak.ps1`：固定程序副本、独立存档、实际经过时间及按分钟采样；不会修改主实例。

模拟服务只验证程序流程，不替代真实模型的语义效果验证。长时间记录明确保留运行版本
散列、实际起止时间及间隔；加速的策略测试不会冒充数小时真实运行。

### 仅现有人设的隔离验证

`tools/PersonalityLab.ps1 -PersonaOnly -PrivateReports` 只复制 `persona.json` 和
`stages.json`，使用独立存档和合成对话；关闭 Skill、电脑操作、真实截图及参考阅读。
该模式拒绝非私密报告、额外参考阅读、替换为合成人设及字符目录中的额外文件。
真实 API 调用仍须明确授权并受独立预算限制；原始回复和执行轨迹保留为加密报告。
这类短样本可检查工具回执和持久化，不能替代长期人设或睡眠周期验证。
