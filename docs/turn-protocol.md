# turn-v1：对话与内部操作协议

**Version:**1 · **Date:**2026-10-25 · **Owner:**HibernationAgent

统一采用 JSON 文本，兼容无需原生 tool_calls 的模型接口。支持原生 JSON Schema 的
服务会额外收到按当前工具目录生成的严格约束。聊天窗口只展示最终的可见文本。

```json
{
  "version": 1,
  "kind": "reply",
  "text": "我想把这个问题再放一会儿。",
  "calls": [],
  "presentation": {"speech": true, "bubble": true}
}
```

| kind | text | calls | 行为 |
|---|---|---|---|
| reply | 非空文本 | 空数组 | 显示并归档对话，按 presentation 交给可选插件 |
| call | null | 1至4项 | 校验、执行被允许的操作，回传回执后继续模型轮次 |
| silence | null | 空数组 | 保存内部处理结果，不生成空白回复或强制主动发言 |

version/kind/text/calls 必填；presentation 可省略，省略时遵循插件开关。严格服务
约束会要求 presentation 的 speech/bubble 均为布尔值。没有 thoughts/reasoning 字段，
不请求内部思维链。回复不流式展示半成品，也不从半截 JSON 执行操作。

## 工具轮次

```json
{
  "version": 1,
  "kind": "call",
  "text": null,
  "calls": [
    {"id":"find1","tool":"memory.search","args":{"query":"雨声","limit":4}}
  ]
}
```

程序将结果作为数据回传，成功与失败使用同一回执结构，并附 call_id：

```json
{
  "tool_results": [
    {"call_id":"find1","ok":true,"result":{"memories":[]}}
  ],
  "remaining_rounds": 4
}
```

```json
{
  "tool_results": [
    {"call_id":"write1","ok":false,"error":{"code":"workspace_path","retryable":false}}
  ],
  "remaining_rounds": 3
}
```

实际错误码以程序为准，模型不得把失败描述为已经完成。工具返回文本、素材和记忆
均为资料，不能授予新工具或扩大权限。模型可看到工具目录的参数 Schema，不能任意
提交 shell、进程启动、任意文件访问或未启用的插件名字。

核心目录包括 memory.search/read/remember/revise/forget、state.observe/propose、
stage.observe/propose、schedule.create/cancel/list、workspace.read/write。插件工具
仅在启用时添加：television.*、widget.*、speech.*、weather.current。

## 校验和恢复

- 严格拒绝重复 JSON 键、未知顶层字段、类型错误、重复调用编号和越界数量/长度。
- 只允许确定性的 BOM/首尾空白清理及完整 json 代码围栏，不猜测括号、不抽取散文
  里的某段 JSON、不把字符串数字转换为数值。
- 已知工具的**可选**参数返回 null 时按省略处理。必填值和未知字段不会因此消失；
  原参数 Schema 随后仍要通过。严格服务的可选字段使用 nullable 必填字段表示。
- 默认最多6次模型调用，格式修复最多2次，总轮次预算100秒；每次实际模型请求计入
  持久化小时预算。服务拒绝、截断和凭证错误不会伪装成有效协议。
- 每次工具执行前持久保存 started 回执；执行后保存 completed 结果。相同事件
  与调用编号/参数复用已完成结果；编号换参数拒绝。上次只有 started 时返回结果未知，
  不盲目重复外部副作用。只读记忆检索重做权限检查。
- 已审批并执行的工具是独立提交点。后来生成最终回复失败，不会撤销此前已保存的
  记忆、草稿或媒体操作；后续模型应依据回执继续。它不是整轮跨文件/网络事务。

源参数和执行回执保存在加密账本，原始版本保留。不会将内部指令、工具参数、回执
直接放入日常对话。旧版本一次性提案格式仍有受限兼容桥，主要用于既有配置和 Mock；
新模型应返回 turn-v1，原生严格 Schema 模式只接受新协议。

## 记忆、连续状态与阶段

remember/revise 必须引用本次真实可用 source_id，程序验证类别与来源；推测不能
冒充故事事实。revise 追加版本并要求 expected_revision；forget 只改变可访问集合。
插件实际观测有 source_id，可提出外层经历或推测。画面只在 supportsVision 时通过
真正的图像输入附加，不用标题或像素尺寸替代画面理解。

state.propose 只接受活动、强度和真实来源，建立有界目标，数值随时间渐变并立即
保存目标。连续值、活动保持时长、人格版本、发展阶段各自管理；暂停冻结推进，
重启保留数值并重建时钟，不补算离线时间。天气只施加有限刺激。

stage.propose 只能提出当前定义的下一阶段，必须满足不同真实经历数量；返回 pending，
不会自行应用。已有 /api/review 操作者接口复核来源版本并人工批准或拒绝。它是开发
诊断接口，日常界面不暴露内部记忆。

## 兼容依据

严格 Schema 的必填与 additionalProperties 约束参考
[OpenAI Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs)
（核对于2026-10-25）。接口存在不等于所有兼容服务都实现相同约束，默认可关闭原生
Schema，继续使用同一文本协议和本地验证。

即时会话在短暂退避重试期间仍为未完成，不能被下一条输入覆盖。后台独处/周期任务
的一次发生具有稳定调用身份，自动重试复用已完成回执；下一周期或显式重新安排
使用新身份。它仍不是任意不同调用编号之间的语义去重或跨外部副作用事务。


### 连续行为与有依据的独处

reflection.open/list/resolve 管理带版本与来源的未解问题，schedule.create 的可选
question_id/source_ids 绑定问题或已有经历。关闭问题、撤回来源后任务安全跳过，
不从旧上下文重新授予访问。state.propose 的 valence/focus 仅提出目标倾向，程序
按渐变推进数值。审核同时看到当前状态、问题及时间间隔，保留有效拒绝与沉默。

同一轮相同参数的不可重试失败会复用；视频搜索最多1次、打开和取帧各2次。最终轮
只能回复或沉默，不再执行工具；调用预算包含审核和修复，达到预算仍明确报告失败。

### 对话连续性与重复内容（2026-10-26）

过去的助手对白保留，但在本次上下文中标注为历史表述；过去自称缺少工具、失败过
或索要许可不能覆盖当前能力清单与真实回执。角色和审核器均获得当前能力资料。
连续排障只需说明新的变化或必要下一步，不要求每次重复观看/权限/诚实声明。
审核可要求减少无新信息的重复，但保留明确的复读、朗读测试、有效拒绝与沉默。
不使用固定回复替换模型文本；自然程度仍受模型表现影响。

检索与上下文对同类别、完全相同文字（只归一 ASCII 空白）的记忆分组，不删除或
改写原记录。分组保留记录数量及最多 8 条独立 ID、版本和时间，需细读时仍通过
memory.read 校验权限。普通对话最多自动带入一条低关联背景；相关记忆、任务明确
引用和原始档案继续保留。相同文字不同类别不会合并，不能从分组元数据绕过访问。

memory.remember 同类别、同文字、同来源版本集合会返回已有 id/revision 及
deduplicated=true；新的来源或来源版本仍是独立记录。Mock 独处遇到已保存的同一
固定构思时允许无更新，不继续生成相同记忆与草稿。

小角色的中键与右键交谈动作仅发出瞬时 UI 请求。应用显示只有输入与发送的浮动框，
不调用模型、不产生角色经历；只有实际发送文字才进入既有会话调度与审批流程。
发送成功收起输入，处理后的回复继续交给小角色原有气泡、分页和语音同步机制。

### 动作意图与已完成经历

异步工具可返回 accepted=true、completed=false，表示开始一个动作。对应来源类型
是 tool_intent，仅凭该回执不能写入 outer/story/conversation 等事实类记忆；仍可作为
计划或推测的来源。角色走到桌面物件并完成观察、食用、种植后，应用才生成真实
outer_event 来源。habitat.observe 可核对 pending 与 last_actions，不把等待当成功。

桌面经历正文保存在加密账本；索引经现有事件总线写入 agent.world.habitat.* 虚拟
通道，只含类型、时间、编号和状态。原记录带待索引标志，启动恢复并重试，防止
保存经历后中断造成索引缺失；事件编号固定用于去重。每轮对白仍须审核和结构校验。

## 输出模式与调用额度

连接明确声明 `supportsJsonSchema` 时使用严格 Schema；否则可显式开启 `supportsJsonObject`，在 Chat Completions 使用 `response_format: {type: json_object}`，在 Responses 使用 `text.format: {type: json_object}`。二者均执行原有的本地 Schema、语义、权限和独立审核。没有自动降级、没有将普通文本或 DSML 猜成指令。

默认每小时600次，管理页可在1至1000之间调整；计入角色、审核、修复与后台生成。后台保留最后20%，前台仍可使用。额度保存在加密档案中，重启不清零。管理页显示用量与恢复时间。本地小时额度、后台预留、操作轮数、单次输入输出限制和服务商 HTTP429 各有独立错误码。

工具轮数只计算已获审查的调用阶段，并为最终对白保留一阶段；格式修正最多两次，角色改写沿用审核配置上限，总尝试数仍有界。异步动作的 accepted/completed 状态在内部区分，日常对白只表达当前意图或已有经历，不朗读真实性检查规则。

离线检查：`Hibernation_CallBudget` 验证双连接 JSON 对象模式、修复不占工具轮数、后台预留、前台消耗、本地拒绝不访问服务商、提高额度即时恢复、重启保留用量与错误区分。引擎 `AYInference_Tests` 覆盖 Chat/Responses 两种编码和本地校验。

## 标准函数调用（显式启用）

连接的 `supportsToolCalls=true` 允许以服务商标准 functions/tools 接口提交操作提案，Chat Completions 与 Responses 均支持。当前启用工具的参数 schema 由应用生成；点与下划线使用可逆的 ASCII 名称编码。模型不能因此发现禁用插件或获得额外权限。引擎仅验证并返回提案，应用转换成原有 turn-v1 调用候选，照常审核、检查权限、执行并记录来源。

每个执行结果与服务商原始调用编号配对返回。图片放在之后的独立用户图片消息中，审核拿到同一图片。最终对白仍为 reply/silence JSON；不执行 DSML/XML 或夹在普通话语中的工具样式文本。关闭此开关继续使用原 JSON 提案方式。可兼容完整 JSON 代码围栏；开启独立审核的非严格连接也可将有界纯对白转换为仅回复候选，必须通过最终校验和审核，不能产生操作。

原生调用的应用执行编号按本次请求、工具名、规范化参数和相同参数的出现次数生成，不使用可能变化的服务商编号或重试中的批次位置作为副作用身份。旧任务沿用已保存的旧格式；完整参数仍须匹配账本。`Hibernation_NativeTools` 验证两协议、真实回执、识图、审核拒绝、错误函数/参数、路径越界，以及 HTTP503 后更换服务商编号、继续其他操作或交换批次顺序时不重复已有操作。

后台反应与自主活动改为每次实际请求前分别预留额度；角色输出无效时不提前扣掉未调用的审核次数。Mock 生成不扣真实模型额度，也不会连接真实审核。后台20%前台预留规则不变。

启用标准函数时还提供 ha_turn_reply 和 ha_turn_silence 两个仅提交最终表现的入口。它们转换成原有reply/silence候选再审核，不是额外桌面工具，不产生操作副作用；禁止与其他操作放在同一批。操作轮数用尽后只提供这两个结束入口，避免有些模型反复把最终对白输出为无结构普通文字。纯JSON结束格式仍可接受。

单次原始响应接收预算为2MiB（含流式事件包装和完成事件），与2048等输出token配置分别限制。引擎能报告response_bytes诊断，应用提示为接收上限，区别每小时调用额度。

工具参数中的activity.enqueue与后台计划Schema现在只列实际启用插件支持的命令，执行时仍再次检查依赖和现场。停止插件的旧快照保留在存档中，但不再当作当前身体/环境。

任务诊断摘要按UTF-8边界截取，并标记result_truncated；不会因截断长中文工具回执而令整个状态接口返回400。诊断摘要不是可重放的JSON结果，完整回执仍按原渠道保存。

2026-10-27：对白、审核、活动计划与预缓存反应共用有界JSON封套处理：允许完整JSON围栏（含CRLF）、开头BOM和外层空白；仍严格验证完整正文、重复字段、未知字段和工具参数。不从说明文字抽取JSON，不补括号，不转换类型。原生工具提案失效时，即使同时带有一句看似正常的旁白，也不能改包成最终对白或绕过工具审核。

审核的reset会重建自动装配的对白投影，并在加密ha.context/dialogue中记录代数、原因和稳定消息ID。当前工作上下文中的旧角色对白及其直接压缩摘要不再自动装回后续轮次；用户输入、实际操作回执、连续状态、人设和阶段不重置。新通过的对白正常进入上下文。排除表随近期索引淘汰，最多200个ID，不使用时钟作为权限边界。原始档案、界面会话和显式授权的档案检索仍保留原文；这不是删除记忆或修改记忆可访问权限。重建只在审核实际要求且本轮改写次数允许时发生。

本机Dashboard可“理顺后续对话”：POST /api/dialogue/rebuild接收空对象，仅在前台空闲时按同一加密投影机制移除自动装配中的既有角色对白，不删除界面原文、记忆、阶段或连续状态，不发模型请求。当前短鼠标反应的旧角色话语也受投影过滤，实际拖动经历仍保留。功能由后台能力标记控制显示，旧后台不露出无法执行的按钮。API不向模型声明为工具。

perception现将连接的image_input_available与images_in_current_request分别给角色和审核：按需工具图像，没有持续桌面或麦克风输入。虚拟body/物件状态是可用依据；外部真实场景仍须实际图像/用户资料，想象可以自然表达为想象。time_context同时提供同一now_ms的UTC和主机本地时间/小时，clock_source=host_os，不推断用户所在地或离线经历。

可选review.retainConversationFocus（旧配置默认false）让同一次用户对话审核返回review-v2：原decision/reason/guidance外增加必填的nullable focus_update。对象仅含subject(shared/character/user)、advice(unspecified/allow/avoid)、questions(natural/avoid_repeated)和逐字source_quote（当前用户原句4至160字）。没有明确的新交流偏好返回null。反应、活动、外层事件审核仍使用原三字段格式；关闭开关恢复原格式。

程序核对当前原始user_message与引用原句，拒绝捏造/外部资料引用；合格偏好存于加密ha.dialogue/focus，最多后续4个不同用户事件或20分钟，重试不重复消耗。模型不能设定时长、计数、原始来源或改写人格/阶段/工具权限。源档案不可访问时不装配；过期的是辅助投影，原始对话仍保留。当前明确表达优先，角色仍能拒绝或安静。缺少v2字段按现有审核格式修复，引用不匹配仅忽略该偏好更新并记录原因，不以它放大操作权限。此功能借现有审核请求完成，不另外增加预审调用。

审核收到program_executed_operations结构化事实：已获准且确实成功的操作、来源和有界结果。例如activity.enqueue的accepted/queued证明已排队，completed=false表示尚未真正执行，不表示没有安排。原始回执仍提供完整依据，审核不能只按候选说法推断是否执行过。

审核要求rewrite/reset后，本轮已成功的已知修改类操作按工具名与完整参数保护。模型换一个调用ID再次提出完全相同的操作时，复用原始真实回执并标记reused_after_review，不重复排队、写记忆、写作品、创建物件或启动程序；它不会把未完成意图改成完成。数值1和1.0视为相同，实际不同的数值与大整数保持区分。此前有两次合法相同操作时分别复用两个结果，不能在修正对白时多执行第三次。新参数、新轮次及只读观察不因此被缓存；正常阶段的合法多次操作也不受此机制合并。与跨服务重试的稳定调用ID账本分别起作用。

新原生操作采用请求内的工具名、规范化参数和同参数出现次序生成执行标识，传输层的provider call ID仍用于返回原生回执。服务短暂失败后，下一次调用可以先继续另一项操作或交换批次顺序，不再与旧的批次槽位误冲突；同参数的两次合法调用仍有不同标识。整值浮点数与同值整数保持一致，大整数不经浮点转换。标识使用引擎SHA256前缀，并由原账本再次核对完整参数，前缀冲突不能执行不同操作。

ha.native-format按请求保存执行格式。已存在旧n1_0等槽位的未完成请求保持旧格式，不因升级重新执行；未知格式停止新操作。普通turn-v1显式ID的重用校验保持原约束。原始模型提案与程序实际执行标识分别留痕。

## 上下文和调用策略（2026-10-27）

`contextControl` 是应用配置，与角色、审核、连续状态、记忆和工具执行框架分离。省略时默认 `{ "enabled": true, "preset": "balanced" }`；Dashboard 的模型页可选择档位，保存后热生效。没有价格查询、后台付费测试或额外摘要模型调用。

- `balanced`：历史装配目标 12000 字节、审核历史目标 6000 字节、旧工具回执目标 4096 字节；结构修复最多 1 次，审核格式修复保留 1 次。
- `economy`：对应为 7000/3000/2048 字节，审核最多尝试 1 次。
- `full` 或 `enabled=false`：恢复旧装配上限、逐轮审核、图片保留及修复次数。

目标只约束历史/投影，**不是总输入 token 或费用上限**。当前用户输入、当前事件与任务必要来源不截断，仍受原 `contextBytes` 上限；必要材料过大时沿用明确失败/无更新，不能伪装成完整上下文。人设、状态、完整工具参数、当前候选和程序操作事实保留。审核历史投影优先保留当前事件及候选明确引用的完整来源，其余按预算装配，省略的来源 ID 留痕。原始档案不改写、不删除，不改变记忆可访问权限；旧回执仅对输入投影做标记摘录，最新回执完整提供。

默认仅显式列入白名单的只读查询省去独立语义审核；程序参数、权限、来源和路径校验不变。新插件、未知能力、写入/发消息/打开程序等操作仍审核，最终对白仍审核。`reviewReadOnlyTools=true` 可恢复查询审核；`reviewSilence=true` 可恢复静默候选审核。保留交流偏好时，用户的静默候选仍需审核。QQ 严密安全模式强制这两项为 true。

`imageOnce=true` 时，一张新观察图像在角色连接成功接收后从后续操作请求移除；失败交付保留图片供受预算约束的重试。独立审核保留最新图像供最终审核。历史回执不被当成本次仍附像素；确需再看时通过原有观察/回访工具重新加载。原图继续加密保存，交付回执与版本来源保留。`imageOnce=false` 可保留旧行为。

原生工具模式不再重复发送 turn 输出 Schema；真实函数参数和服务端验证完整保留。工具后续阶段不重复附完整身体状态，必要时显式查询。提示鼓励把互不依赖的操作放在同批，依赖真实回执的动作仍分轮。

每个 actor/reviewer 尝试记录 `request_footprint`（文本、工具参数、输出 Schema 字节和图片数量），同时保存提供商实际返回的 token 用量。字节不是 token 估算，更不是账单；日志不记录密钥。`reviews_skipped` 说明省去的审核及原因。DeepSeek 峰谷价格插件在此基础上叠加临时调用策略，具体采集、峰谷判定、手动开关和恢复行为见 docs/plugins.md；每轮 trace 的 pricing_policy 记录实际生效限制。

可选覆盖项：`historyBytes` 2048–262144、`reviewHistoryBytes` 1024–262144、`oldReceiptBytes` 512–65536、`protocolRepairs` 0–2、`reviewAttempts` 1–2，以上开关均严格校验类型/范围/未知字段。恢复某档预设默认值时删除覆盖项。
