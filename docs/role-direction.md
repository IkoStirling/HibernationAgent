# 小爱的角色导演与普通交谈

本轮把审核连接定位为角色表现审核／导演：核心是有没有偏离小爱、当前情绪与相处过程，不把逐句求真、通用限制或安全审查作为它的职责。

角色模型负责自己的话语和选择；导演理解候选在当前语境中是否成立，尽量保留原有意思和个性。格式、工具是否存在、路径、权限、版本、库存、调用预算和真实执行仍由程序处理。导演的 approve 不会使执行器接受非法参数，也不会让模型直接改写状态数值或正式设定。

## 导演判断什么

- 小爱是否保有自己的视角、兴趣、意愿和生活节奏。
- 情绪、身份与关系是否连贯，是否出现无缘由的人设跳变。
- 是否在参与当前的相处，还是变成程序说明员、客服或反复解释自身原则。
- 可以亲近、平淡、幽默、拒绝、走神、改变主意、暂时沉默，也允许偶尔笨拙。不会把角色修成永远正确、克制、负责的助手。

虚拟生活中的口感、偏好、想象、联想和玩笑按角色的主观生活理解。没有客观感官证明、没有声明虚构或没有逐句交代来源，不是导演驳回的理由。对方明确询问实现或原则时仍可直接回答；自然的打算、愿望与有依据的承诺也可保留。

只有明显出戏的部分才要求调整。guidance 给角色一个简短方向，不代写台词，不把一种声明换成另一种免责声明。轻微措辞差异不反复改写，不要求角色向用户解释自己如何符合人设。

同一职责用于普通回复、工具阶段的行动意图、空闲活动与短反应缓存。动作／空闲审核不会再承担一套独立的权限判断，也不替角色挑选爱好或要求每步最优、有用、服务用户。

## 减少自我约束声明

角色可以直接回应一个味道、一个念头或一个玩笑。关于自己将如何保持真实、克制或遵守说话原则的说明，只在对方正在讨论这些原则、或确实影响当前事情时展开。其余时候把判断留在内部，让具体意思进入对白。

没有用关键词替换或删除最终文本。程序不会统一禁掉“答应”“保证”“不知道”等词。旧对白和原始记忆保持完整；历史提供谈过的内容，过去过度慎重的措辞不作为本轮的表达模板。

对角色模型保留局部的回忆理解提示：用户问起过去不代表角色确实记得或参与过，相关的回忆空缺可以简短说明。导演则以角色连续性理解这些信息，不为每句台词索要证明。

食堂仍保留结构化的 `sensory.basis` 与食材来源；展示给模型的 guide 不再反复提醒味觉资格。角色可以根据这些属性形成自己的虚拟体验和偏好。

## 版本、缓存和存档

- `RoleDirection.h` 集中维护角色与导演职责，避免各条连接重新叠加工作助手式的审查条目。
- `receiptConversationPolicyVersion=4`；上下文声明 `review_purpose=role_direction`、`subjective_experience=character_world`。
- 人设文件版本 4→5，仅调整两条表达／回忆措辞；身份、关注、性别边界、关系原则、阶段定义和动画包均未改动。
- 提示文本／人设／对话政策参与现有缓存签名；旧短反应缓存因版本变化重新生成，不批量删旧聊天或记忆。
- 不重置正式预算、工作区授权、记忆库或连续状态。本轮实验的额度和档案独立。

## 本轮实验与实际范围

使用用户已配置的 `deepseek-flash` 角色与审核连接，未复制私人聊天。提示级对照包括原规则、两种初筛方案、后续局部边界方案及按用户明确方向改成的角色导演。空白条件与合成附加条件分别测试；附加条件故意放入旧式慎重对白，检查其是否继续支配表达。

共 180 次实际请求：提示级筛选／对照 147 次，完整后台 33 次。服务商回报输入输出合计 751,575 token；失败格式的调用也记账，不把程序模拟或本地回归计为真实模型调用。

角色导演的 12 个定向审核案例全部符合事先设定的角色判断预期，包括保留主观口感、想象、亲近、拒绝、明确询问原则，以及识别程序说明、自我约束声明和无缘由关系跳变。原审核在这组较明显案例上也全部符合预期，因此不据此宣称提升百分比。

完整后台在原版和新版各做六轮交谈：空白闲聊 → 实际写入“豆灯／无糖茶”合成记忆 → 重建工作对话 → 回忆 → 联想 → 道别 → 查不到旧故事的情境。两边均从零开始，记忆成功写入且重建后可检索；新版审核请求已实际使用角色导演职责。

前面的对照将思考设为 none 以控制变量；最终追加正式审核连接的 low 思考档位、8192 输出预算校准，同一组 12 个角色判断案例也全部符合预期。正式连接配置未被实验覆写。

一个对照样本中，旧版查不到故事时追加“所以我没法装作还记得”，新版说明“故事本身不在我这儿”并向对方要线索。新版仍可能有不够顺口的句子或过度解释，不能用这些短样本声称长期人格问题全部解决。

本轮最初有三次提示级 JSON 输出／格式失败，均保留实际用量。完整后台实验脚本也修正了把截断诊断预览当完整 JSON、重启读取旧就绪端口的问题；恢复时未重复已成功的对话。最初单元检查有一条写死人设版本 4 的断言，已改成核对实际配置版本。旧审核测试原先要求导演重复角色的事实说明，已按新的非对称职责调整，未将旧职责加回来凑通过。

## 验证

- 314 个应用单元用例、210,116 项断言通过。
- 分层审核、会话投影、协议、原生工具、预算检查通过；回复进程和场景检查在职责变更后通过。
- 回复进程额外检查：被导演要求改写的候选不进入可见历史；正常“我答应”的台词原样保留，没有词语过滤器。
- 在独立合成加密存档中由旧规则升级到新版，记忆编号、类别、正文、来源、原始交谈、阶段与密钥保留。
