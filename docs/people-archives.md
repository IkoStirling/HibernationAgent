# 人物档案第一版

角色可用 people.current、people.search、people.read、people.note。人物由可信桌面/QQ适配器确定，工具不能传入他人身份或文件路径。桌面与开启共享的号主私聊使用 owner；隔离模式、其他账号、群聊在各自会话存档根建立独立目录，不凭昵称自动合并，也不把私聊认识带进群聊。

存放于对应存档根 people/稳定编号/records.sqlite，采用现有 Vault HV2 加密及父存档根的 memory-key.dpapi。备份时必须连同父根的密钥/便携恢复包保留，不能只拷贝人物文件夹。MemoryWorkshop 的递归备份会按 SQLite 快照收录这些数据库；便携恢复保留同一父根主密钥后可读取，人物库不另生成机器绑定密钥。身份目录只包含程序编号，账户资料不作为明文目录名。

fact、preference 表示有原句的明确表达；impression 固定标记 tentative，最多30天有效；journal 固定为 subjective。所有写入须提供该对象可访问的原始用户消息、精确引句与版本。不能用其他人的原话或隐藏来源。程序验证来源和引句，不声称能完全证明模型释义与原文语义相同。每次修订追加版本；撤回使用同一id、expected_revision及新来源，status=revoked，原记录仍保留。旧时间的来源不能覆盖较新的认识。每个目录最多256个主题，单次检索12项，历史读取有界；不删除原始交谈。

普通上下文只选择最多4项、4000字节，与当前话题相关的认识以及明确偏好。过期、撤回、来源隐藏、来源修订失效的条目不进入检索/上下文；按id查看可访问的旧版本会标明过期/撤回。模型被明确告知：不强行提及旧事，不必每轮记录，不需报告“我记住了”。个人档案不作为权限、人设或心情数值。工具读写经现有路由、Skill、预算、回执与重复执行保护；读工具走程序校验，写入仍遵循当前角色审核策略。

第一版没有自动从全部历史构建人物画像，没有新增每轮整理调用、自动跨账号合并、画像关系打分或独立后台压缩任务。角色可主动补记、检索、修订和撤回；后续后台整理可作为单独任务接入，不扩大现有审核职责。

检查：People 单元覆盖身份、到期、版本、来源过滤与落盘加密；LayeredReview 覆盖真实进程写入/检索及错误引句、来源隐藏；OwnerContinuity_native 覆盖QQ号主到桌面、重启延续、其他用户及群聊隔离。测试使用合成资料与本机模拟服务，不发送真实QQ消息或调用付费模型。

## 同批修复：QQ共享来源校验

内部固定来源的 get 与面向角色的档案浏览曾共用聊天分类过滤。共享的工具观察可作为内部状态的来源，但不属于聊天档案浏览分类，因而QQ会在调用模型前误报 context_authorization_changed。现在内部跨根按确切ID核对来源使用 nativeProvenance 模式，继续保留来源隐藏、递归可见性、字节预算、目录与版本校验；普通档案浏览的分类不扩大。回归测试同时确认内部能核对工具观察，以及隐藏来源后内部仍拒绝。此修正不删除记忆、不解除权限检查、不重启NapCat。
